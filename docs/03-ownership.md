# 03. Ownership, borrowing и lifetimes

Это главная тема Rust. Если понять её, остальной язык становится предсказуемым. Если пытаться писать «как на Python/Java», компилятор будет постоянно ругаться.

---

## Зачем это нужно

В Python и Java памятью управляет сборщик мусора: объект живёт, пока на него есть ссылки. Это удобно, но:

- GC работает в рантайме и иногда непредсказуемо тормозит;
- циклические ссылки надо собирать отдельно;
- в Java всё равно можно получить `NullPointerException` и утечки;
- в Python — забыть закрыть файл или получить гонку.

Rust заменяет GC **статической проверкой владения**. Компилятор ещё на этапе сборки доказывает, что:

- память освободится ровно один раз;
- не будет использования после освобождения (use-after-free);
- не будет двух одновременных изменений одного объекта (data race);
- не будет висячих ссылок (dangling references).

За это платят временем компиляции и необходимостью явно думать о владении.

## Стек и куча

```text
let s = String::from("hello");

Стек (фиксированный размер)          Куча (динамический размер)
┌──────────────────────┐            ┌───┬───┬───┬───┬───┐
│ ptr ─────────────────┼───────────▶│ h │ e │ l │ l │ o │
│ len = 5              │            └───┴───┴───┴───┴───┘
│ capacity = 5         │
└──────────────────────┘
```

`String` на стеке — это маленькая структура из трёх полей: указатель, длина, вместимость. Сами байты лежат в куче.

Когда `String` выходит из области видимости, вызывается `drop`, и память в куче освобождается. Никакого GC.

---

## Три правила владения

1. **У каждого значения ровно один владелец.**
2. **Когда владелец выходит из области видимости, значение уничтожается.**
3. **Владение можно переместить (move) или одолжить (borrow).**

---

## Move: перемещение владения

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1; // владение переместилось из s1 в s2

    // println!("{s1}"); // ошибка E0382: borrow of moved value
    println!("{s2}");     // OK
}
```

Что произошло: скопировалась только структура на стеке (ptr/len/capacity), а куча осталась той же. Теперь `s2` — единственный владелец. `s1` компилятор считает недействительным, чтобы не было двойного освобождения.

Это не «поверхностное копирование» и не «глубокое копирование» — это **перемещение**.

### Move в функцию

```rust
fn consume(s: String) {
    println!("{s}");
} // здесь s уничтожается

fn main() {
    let s = String::from("hello");
    consume(s);
    // println!("{s}"); // ошибка: s перемещена в consume
}
```

Если функция должна только прочитать — бери `&str`:

```rust
fn print_it(s: &str) {
    println!("{s}");
}

fn main() {
    let s = String::from("hello");
    print_it(&s);          // заимствование
    println!("{s}");       // OK, s всё ещё наша
}
```

### Move из функции

```rust
fn make_greeting(name: &str) -> String {
    format!("Привет, {name}!")
}

fn main() {
    let greeting = make_greeting("Аня");
    println!("{greeting}");
}
```

Функция создаёт `String` и возвращает владение вызывающему. Это нормально и эффективно (обычно без лишнего копирования благодаря move/RVO).

## Copy: типы, которые копируются

Некоторые типы не перемещаются, а копируются побитово. Они реализуют трейт `Copy`:

- все целые (`i32`, `u64`, ...), `f32`, `f64`, `bool`, `char`;
- кортежи и массивы из `Copy`-элементов;
- ссылки `&T` (сама ссылка копируется).

```rust
let x = 5;
let y = x;       // копирование, x остаётся валидным
println!("{x} {y}");

let a = [1, 2, 3];
let b = a;       // массив из i32 — Copy
println!("{a:?} {b:?}");
```

`String`, `Vec<T>`, `HashMap` — **не** `Copy`, потому что владеют кучей.

### Clone

Если нужно именно глубокое копирование — явно:

```rust
let s1 = String::from("hello");
let s2 = s1.clone(); // копия данных в куче
println!("{s1} {s2}");
```

`clone()` может быть дорогим. Не ставь его автоматически, чтобы «успокоить» компилятор. Сначала спроси: можно ли одолжить?

---

## Borrowing: заимствование

Ссылка `&T` позволяет читать значение, не забирая владение. Ссылка `&mut T` позволяет изменять.

### Правило заимствования

В любой момент времени для одного значения можно иметь:

- **любое количество** `&T` (читателей), **или**
- **ровно одну** `&mut T` (писателя),

но **не одновременно** и то, и другое.

Это правило предотвращает гонки данных ещё на этапе компиляции.

```rust
let mut s = String::from("hello");

let r1 = &s;
let r2 = &s;
println!("{r1} {r2}"); // сколько угодно читателей

let m = &mut s;
m.push_str(" world");
println!("{m}");
```

А так нельзя:

```rust
let mut s = String::from("hello");
let r = &s;
// let m = &mut s; // ошибка E0502: cannot borrow as mutable
println!("{r}");
```

И так тоже:

```rust
let mut s = String::from("hello");
let m1 = &mut s;
// let m2 = &mut s; // ошибка E0499: cannot borrow as mutable more than once
m1.push('!');
```

### NLL: заимствование заканчивается на последнем использовании

Современный Rust использует **non-lexical lifetimes**: borrow живёт не до конца блока, а до последнего использования ссылки.

```rust
let mut v = vec![1, 2, 3];

let first = &v[0];
println!("{first}"); // последнее использование first

v.push(4);           // OK: заимствование уже закончилось
println!("{v:?}");
```

Если переставить `v.push(4)` перед `println!("{first}")` — будет ошибка, потому что `first` ещё будет использоваться после изменения.

### `&mut` не означает «всегда mutable»

```rust
let x = 5;
// let y = &mut x; // ошибка: x не объявлена как mut
```

Чтобы взять `&mut`, сама переменная должна быть `mut`:

```rust
let mut x = 5;
let y = &mut x;
*y += 1;
println!("{x}"); // 6
```

Ссылка `&mut T` даёт **эксклюзивный** доступ. Пока она жива, никто другой не может ни читать, ни писать.

## `String` vs `&str`

Это два разных типа, и их путают чаще всего.

| | `String` | `&str` |
|---|---|---|
| Владение | владеет данными в куче | срез, не владеет |
| Размер | ptr + len + capacity | ptr + len |
| Изменяемость | можно менять при `mut` | только читать |
| Где использовать | хранить строку, возвращать новую | принимать параметром, смотреть на часть |
| Пример | `String::from("hi")` | `"hi"`, `&s[..]` |

Правило проектирования: **принимай `&str`, возвращай `String`**, если создаёшь новую строку.

```rust
fn greet(name: &str) -> String {
    format!("Привет, {name}!")
}
```

`&String` автоматически приводится к `&str` через deref coercion, поэтому `greet(&my_string)` работает.

Строковые литералы имеют тип `&'static str` — ссылка на данные, скомпилированные в бинарник.

---

## Срезы

Срез — это ссылка на непрерывный кусок коллекции.

```rust
let arr = [10, 20, 30, 40, 50];
let slice: &[i32] = &arr[1..4]; // [20, 30, 40]
println!("{slice:?}");

let s = String::from("Привет, мир");
let hello = &s[..6];  // осторожно: индексы в байтах, не в символах!
println!("{hello}");
```

Для строк с Unicode лучше использовать методы, а не байтовые индексы:

```rust
let s = "Привет, мир";
for (i, ch) in s.char_indices() {
    println!("{i}: {ch}");
}
```

Срезы массивов/векторов — `&[T]`; строк — `&str`. Это «умные указатели» на существующие данные, без копирования.

## Lifetimes: время жизни ссылок

Компилятор должен знать, что ссылка не переживёт данные, на которые указывает. Обычно времена жизни выводятся автоматически, но иногда их нужно указывать.

### Простой случай: одна входная ссылка

```rust
fn first_word(text: &str) -> &str {
    text.split_whitespace().next().unwrap_or("")
}
```

Здесь lifetime выводится: возвращаемая ссылка живёт столько же, сколько входная. Компилятор применяет **правило элизии**: одна входная ссылка → выходная получает её lifetime.

### Две входные ссылки

```rust
fn longest<'a>(left: &'a str, right: &'a str) -> &'a str {
    if left.len() >= right.len() { left } else { right }
}
```

`'a` — это не «время жизни переменной», а **параметр**: «все эти ссылки живут как минимум `'a`, и результат живёт не дольше `'a`».

Использование:

```rust
fn main() {
    let a = String::from("long");
    let b = String::from("short");
    let result = longest(&a, &b);
    println!("{result}");
}
```

Если попытаться вернуть ссылку на локальную строку — ошибка:

```rust
// fn bad() -> &str {
//     let s = String::from("hello");
//     &s // E0515: returns a value referencing data owned by the current function
// }
```

Решение: вернуть `String` (передать владение) или принять ссылку снаружи.

### Lifetime в структуре

Если структура хранит ссылку, нужен параметр времени жизни:

```rust
struct Excerpt<'a> {
    part: &'a str,
}

fn main() {
    let text = String::from("Rust is fun");
    let excerpt = Excerpt { part: &text[..4] };
    println!("{}", excerpt.part);
}
```

Структура не владеет строкой; она не может жить дольше `text`. Компилятор это проверит.

### `'static`

`'static` — ссылка, живущая всю программу. Строковые литералы — `&'static str`. Не ставь `'static` везде: это обычно признак того, что структура должна владеть данными (`String` вместо `&str`).

## Ownership в функциях: что выбирать

| Ситуация | Параметр | Возврат |
|---|---|---|
| Только прочитать | `&T` / `&str` / `&[T]` | — |
| Изменить на месте | `&mut T` | `()` или результат |
| Забрать владение (редко) | `T` | `T` или другое |
| Создать новое | — | `T` (владеющее) |
| Вернуть часть входных данных | ссылка + lifetime | `&T` |

По умолчанию **бери ссылку**, а не владение. Это делает API гибче: вызывающий может передать и `String`, и `&str` (через deref coercion).

## Владение и коллекции

```rust
let mut v = Vec::new();
v.push(String::from("a")); // вектор владеет строкой
let first = v.remove(0);   // владение строкой перешло в first
println!("{first}");
```

Если положить значение в коллекцию, коллекция становится владельцем. Если коллекция уничтожается, уничтожаются и элементы.

Итерация:

```rust
let v = vec![1, 2, 3];

for x in &v {          // &i32, читаем
    println!("{x}");
}

let mut v2 = v.clone();
for x in &mut v2 {     // &mut i32, меняем копию
    *x += 1;
}

for x in v {           // i32, владение (v перемещён)
    println!("{x}");
}
```

После `for x in v` вектор нельзя использовать — он перемещён. После `for x in &v` — можно.

## Интерьерная изменяемость (кратко)

Иногда нужно менять данные через общую ссылку. Для этого есть:

- `Cell<T>` — для `Copy`-типов, простое присваивание;
- `RefCell<T>` — проверка заимствований **в рантайме**, может паниковать;
- `Rc<RefCell<T>>` — общее владение + изменяемость в одном потоке;
- `Arc<Mutex<T>>` — общее владение + блокировка в нескольких потоках.

```rust
use std::cell::RefCell;

let cell = RefCell::new(5);
*cell.borrow_mut() += 1;
println!("{}", cell.borrow());
```

Это не способ «обойти borrow checker». Используй, только если действительно нужна общая изменяемость (графы, кэши, интерьерные счётчики). В 95% учебных задач достаточно обычного владения.

## Частые ошибки компилятора и что они значат

### E0382: borrow of moved value

```text
error[E0382]: borrow of moved value: `s`
```

Значение переместили, а потом пытаются использовать. Решения:

- использовать `&s` вместо `s`;
- вернуть значение из функции;
- `clone()`, если копия действительно нужна.

### E0502: cannot borrow as mutable because it is also borrowed as immutable

```rust
let mut v = vec![1, 2, 3];
let first = &v[0];
v.push(4);          // ошибка, если first ещё используется
println!("{first}");
```

Решения: закончить использование `first` до `push`, скопировать значение (`let first = v[0];` для `Copy`-типа) или перестроить логику.

### E0499: cannot borrow as mutable more than once

Две `&mut` одновременно. Решение: сократить область жизни первой ссылки блоком `{ ... }` или перестроить код.

### E0106: missing lifetime specifier

Компилятор не понимает, с каким входным lifetime связан выходной. Добавь `<'a>` и расставь `'a`.

### E0515 / E0597: возврат ссылки на локальное значение

Функция пытается вернуть ссылку на данные, которые умрут в конце функции. Решение: вернуть владеющее значение (`String`, `Vec`) или принять ссылку снаружи.

## Чек-лист, когда ругается borrow checker

1. **Кто владеет значением?** Если функция забирает `T`, после вызова его больше нет.
2. **Нужно ли владение?** Может, достаточно `&T` или `&mut T`.
3. **Сколько живёт ссылка?** До последнего использования, не до конца блока (NLL).
4. **Можно ли сузить область видимости?** Блок `{ ... }` часто решает конфликт.
5. **Не держишь ли `&mut` дольше, чем нужно?** Например, внутри цикла.
6. **Оправдан ли `clone()`?** Иногда да, но не как рефлекс.
7. **Не пытаешься ли вернуть ссылку на локальную переменную?** Верни `String`/`Vec`.
8. **Не нужен ли `Rc<RefCell<T>>`/`Arc<Mutex<T>>`?** Только если общая изменяемость реально нужна.

---

## Ментальная модель

- **Владелец** — человек, который взял книгу из библиотеки и отвечает за возврат.
- **`&T`** — читательский билет: можно читать, нельзя менять; читателей много.
- **`&mut T`** — редакторская правка: только один редактор, и читателей в это время нет.
- **Lifetime** — срок, на который выдали книгу. Компилятор проверяет, что ты не пытаешься читать книгу после возврата.
- **`clone()`** — купить вторую копию книги. Иногда нужно, но дорого.

Ответы проверяй компилятором и тестами, а не «на глаз».
