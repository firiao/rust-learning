# Входной практикум. Окружение, Cargo и первый цикл «сломал — починил»

Практикум обязателен, но не оценивается как лабораторная. Сделай его до lab01: он проверяет, что инструменты работают, и один раз прогоняет полный путь изменения программы — запуск, ошибка компилятора, исправление, тест.

Если практикум не завершён, сначала разберись с окружением и только потом берись за lab01.

## Цель

Убедиться, что Rust, Cargo, тесты, `clippy` и `fmt` работают, и почувствовать главный цикл разработки на Rust: **компилятор — не враг, а проверяльщик**.

## Подготовительная часть

1. Проверь версии:

   ```bash
   rustc --version
   cargo --version
   cargo clippy --version
   cargo fmt --version
   ```

   Ожидается примерно `1.99.x`. Если `cargo` не найден — сначала поставь Rust, без этого дальше нельзя.

2. Зайди в папку курса:

   ```bash
   cd ~/rust-learning
   ```

3. Убедись, что курс собирается целиком:

   ```bash
   cargo test --workspace
   ```

   Тесты `lab01`–`lab03` частично `ignored` — это нормально, там пока `todo!()`.

4. Запусти примеры:

   ```bash
   ./run_examples.sh
   ```

## Обязательное задание

### 1. Создай свой первый проект

```bash
cd ~ && cargo new hello-rust
cd hello-rust
cargo run
```

Найди в `Cargo.toml` поля `name`, `version`, `edition`. Объясни себе, что такое `edition`.

### 2. Сломай его специально

Замени `main` на такой:

```rust
fn main() {
    let name = String::from("Rust");
    greet(name);
    println!("{name}");
}

fn greet(who: String) {
    println!("Привет, {who}!");
}
```

Запусти `cargo run`. Прочитай ошибку **целиком**, включая подсказку `help:`.

Ответь письменно (в `NOTES.md`):

- какой код ошибки (`E0xxx`);
- какое правило ownership нарушено;
- почему компилятор не дал это скомпилировать, хотя в Python такой код работает.

### 3. Почини двумя способами

- **способ 1:** передай `&name` и принимай `&str`;
- **способ 2:** оставь `String`, но не используй `name` после вызова.

Оба должны компилироваться. Первый — правильный. Второй — рабочий, но объясни, чем он хуже.

### 4. Добавь тест

В том же проекте сделай функцию с тестом (и вызови её из `main`, иначе `clippy` пожалуется на неиспользуемый код):

```rust
fn main() {
    println!("5! = {}", factorial(5));
}

fn factorial(n: u64) -> u64 {
    (1..=n).product()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn factorial_of_five_is_one_twenty() {
        assert_eq!(factorial(5), 120);
    }

    #[test]
    fn factorial_of_zero_is_one() {
        assert_eq!(factorial(0), 1);
    }
}
```

Запусти `cargo test` — оба теста зелёные. Затем сломай реализацию (`1..n` вместо `1..=n`) и убедись, что падает **именно тест на `factorial(5)`**, а тест на ноль остаётся зелёным.

Это важный урок: тест на ноль не ловит такую ошибку. Границы надо проверять с двух сторон — `0` и хотя бы одно обычное значение.

### 5. Прогони проверки

```bash
cargo fmt
cargo clippy --all-targets -- -D warnings
```

Если `clippy` ругается — исправь. Не отключай проверку, пока не поймёшь, о чём она.

## Критерии приёмки

- [ ] `rustc`, `cargo`, `clippy`, `fmt` отвечают на `--version`;
- [ ] `cargo test --workspace` в `~/rust-learning` зелёный;
- [ ] `./run_examples.sh` отрабатывает без ошибок;
- [ ] `hello-rust` создан, собирается и запускается;
- [ ] ты воспроизвёл ошибку `E0382`, прочитал подсказку и починил её двумя способами;
- [ ] в `NOTES.md` записано, какое правило ownership было нарушено и почему;
- [ ] тест на факториал проходит, а после поломки реализации — падает;
- [ ] `cargo fmt --check` и `cargo clippy --all-targets -- -D warnings` чистые.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `cargo: command not found` | Rust не установлен или `~/.cargo/bin` не в `PATH` |
| `linker 'cc' not found` | не установлен `gcc`/`build-essential` |
| `error: could not compile ... (signal: 9)` | закончилась память, закрой лишнее |
| `clippy` не найден | `rustup component add clippy` или пакет `rust-clippy` |
| непонятная ошибка компилятора | прочитай последний блок `help:` — там почти всегда готовое решение |
