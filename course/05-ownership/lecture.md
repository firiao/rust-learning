# Лекция 5. Владение (ownership)

**Время:** ~30 минут

```text
Это самая важная лекция курса.
Если что-то останется непонятным — не иди дальше, напиши мне.
Всё остальное в Rust выводится из этой идеи.
```

**Нужно знать заранее:** `let`, `mut`, типы, `&str` (неизменяемый текст), функции, области видимости.

**Новые слова в этой лекции:**
- **память** — место, где программа хранит данные;
- **стек** — быстрая память для маленьких значений, которая освобождается сама;
- **куча** — память «по запросу» для данных переменного размера;
- **владение (ownership)** — правило Rust: у каждого значения в куче ровно один хозяин;
- **владелец** — переменная, которая отвечает за значение и освобождает его;
- **move (перемещение)** — передача владения другому имени;
- **`Copy`** — свойство простых типов, которые копируются вместо перемещения;
- **`clone`** — явное полное копирование значения;
- **`drop`** — автоматическое освобождение памяти при выходе владельца из области видимости;
- **`String`** — строка, которой программа владеет и которую можно менять.

---

## 1. Проблема, которую решает Rust

Программа хранит данные в памяти. Память не бесконечна, поэтому её нужно освобождать, когда данные больше не нужны.

Есть три подхода:

**Python / Java: сборщик мусора.** Программа периодически сама ищет данные, на которые больше никто не ссылается, и освобождает их. Удобно, но:
- сборщик работает в фоне и иногда «замораживает» программу;
- на это тратятся память и время.

**C / C++: вручную.** Программист сам вызывает освобождение. Быстро, но:
- забыл освободить — память утекает, программа съедает всё;
- освободил дважды — программа падает;
- использовал после освобождения — непредсказуемое поведение.

**Rust: правила, которые проверяет компилятор.** Память освобождается в тот момент, когда значение больше не нужно, и **это проверяется до запуска программы**. Ни сборщика, ни ручного освобождения.

### Стек и куча — минимально необходимое

Память программы условно делится на две части.

**Стек** — маленькая быстрая область. Значения на стеке фиксированного размера (число, `true`, символ). Когда функция заканчивается, её стек «схлопывается» и всё локальное исчезает само. Думать об этом не надо.

**Куча** — большая область «по запросу». Сюда кладут данные, размер которых заранее неизвестен: текст, который пользователь ввёл, список, который растёт. Здесь и возникает вопрос «кто освободит».

Текст, который ты писал в лекции 2 (`"привет"`), — это `&str`: он **вшит в программу** при сборке и освобождать его не нужно. Он всегда одинаковый и всегда есть.

Но программа работает с текстом, который появляется **во время работы**: пользователь ввёл имя, прочитали файл, склеили сообщение. Для этого есть второй строковый тип.

## 2. `String` — строка, которой владеет программа

```rust
fn main() {
    let mut greeting = String::from("Привет");
    greeting.push_str(", Аня");
    greeting.push('!');

    println!("{greeting}");   // Привет, Аня!
}
```

Разберём незнакомое:

**`String::from("Привет")`** — создать `String` из текста. Читается как «внутри типа `String` взять функцию `from` и дать ей текст». Двойное двоеточие `::` — путь: слева тип, справа имя внутри него. Подробно про такие функции будет в лекции 7, сейчас достаточно читать это как «создать строку из ...».

**`greeting.push_str(", Аня")`** — дописать текст в конец строки. `push_str` — **метод**: функция, которая привязана к типу и вызывается через точку. Запись `значение.имя(аргументы)` означает «выполни у этого значения действие `имя`, передав аргументы». Метод автоматически получает само значение, для которого его вызвали, — поэтому `push_str` знает, в какую строку дописывать. Как писать свои методы — лекция 7.

**`greeting.push('!')`** — дописать один символ (`char`, одинарные кавычки — помнишь лекцию 2).

**`mut`** обязателен: мы меняем строку.

Отличие от `&str`:

| | `&str` (`"привет"`) | `String` (`String::from(...)`) |
|---|---|---|
| можно менять | нет | да |
| где живёт | вшит в программу | в куче, создаётся при работе |
| кто отвечает за память | никто (она вечная) | **владелец** |

Вот и появился **владелец** — переменная `greeting`. Она отвечает за текст в куче. И тут начинаются правила Rust.

## 3. Правило первое: у значения один владелец

```rust
fn main() {
    let a = String::from("привет");
    let b = a;                    // владение переходит к b

    println!("{b}");              // ok
    println!("{a}");              // ошибка
}
```

```text
error[E0382]: borrow of moved value: `a`
 --> main.rs:5:16
  |
2 |     let a = String::from("привет");
  |         - move occurs because `a` has type `String`,
  |           which does not implement the `Copy` trait
3 |     let b = a;
  |             - value moved here
5 |     println!("{a}");
  |               ^ value borrowed here after move
```

Разберём сообщение по частям:

- `borrow of moved value: 'a'` — «использование перемещённого значения `a`»;
- `move occurs because 'a' has type 'String'` — «перемещение произошло, потому что `a` имеет тип `String`»;
- `which does not implement the 'Copy' trait` — «который не реализует свойство `Copy`» (о нём ниже). `trait` — механизм Rust для описания свойств типа; подробно в лекции 11, здесь читай как «свойство»;
- `value moved here` — «здесь произошло перемещение» (строка 3);
- `value borrowed here after move` — «здесь использовано после перемещения» (строка 5).

Это называется **move** — перемещение. Строка `let b = a;` **не копирует** текст. Она копирует только «адрес» данных и передаёт `b` право владения. После этого `a` считается пустым — компилятор запрещает к нему обращаться.

### Почему так строго

Представь, что оба имени `a` и `b` считались бы владельцами. Когда `a` умирает — освобождает текст. Когда `b` умирает — освобождает **тот же текст второй раз**. Это двойное освобождение, одна из главных уязвимостей C++.

Rust выбирает простой путь: **раз владелец один, двойного освобождения быть не может**.

### Сравнение с Python и Java

```text
Python:  a = ...      b = a      → две ссылки на один объект, оба живут
Java:    b = a                   → две ссылки, оба живут
Rust:    let b = a               → владение переехало, a больше не жив
```

В Python это выглядит так:

```python
a = "привет"
b = a            # b и a — два имени одного объекта
print(a, b)      # работает
```

В Rust эквивалент Python-кода — это `clone()` (о нём ниже), а не обычное присваивание. Присваивание `String` — это передача, как «отдать ключ от квартиры», а не «сделать второй ключ».

## 4. Правило второе: простые типы копируются

Если попробовать то же самое с числом — ошибки не будет:

```rust
fn main() {
    let a = 5;
    let b = a;

    println!("{a} {b}");   // 5 5
}
```

Почему? Потому что число целиком лежит **на стеке**, у него нет «текста в куче», за который надо отвечать. Копировать 4 байта безопасно — получится два независимых числа.

Такие типы называются **`Copy`** («копируемые»). Это числа, `bool`, `char`, и ещё некоторые типы. Для них `let b = a;` — именно копирование, а `a` остаётся живым.

| Тип | `Copy`? | Что происходит при `let b = a` |
|---|---|---|
| `i32`, `i64`, `f64`, `bool`, `char` | да | копирование, обе переменные живы |
| `String` | нет | move, `a` перестаёт быть доступной |
| `&str` | да | копируется ссылка на вшитый текст |

`&str` — копируемый, потому что это маленькая ссылка на вечные данные, а не владение кучей. Здесь мы забегаем вперёд (ссылки — лекция 6), но это знание пригодится сразу.

## 5. `clone` — когда действительно нужна копия

Если нужны **две независимые строки**, копию делают явно:

```rust
fn main() {
    let a = String::from("привет");
    let b = a.clone();          // полная копия: текст скопирован в новую память

    println!("{a} {b}");        // обе живы
}
```

**`clone`** — полное копирование значения, включая данные в куче. После него `a` и `b` — два разных `String` с одинаковым содержимым. Изменишь один — второй не изменится.

Слово `clone` в коде видно всегда. Это сознательное решение: «я понимаю, что копирую, и мне это нужно».

### Ошибка новичка: `clone` вместо размышления

Компилятор при ошибке `E0382` подсказывает:

```text
help: consider cloning the value if the performance cost is acceptable
```

Соблазн — вставить `.clone()` и забыть. Но правильный вопрос другой: **нужны ли мне обе переменные?**

- если нет — не используй первую, и всё скомпилируется без копии;
- если да, но только для чтения — передавай ссылку (лекция 6), а не копию;
- если правда нужны две независимые копии — тогда `clone`.

Копирование больших данных стоит времени и памяти. `clone` в горячем цикле может замедлить программу в разы.

## 6. Передача в функцию — тоже передача владения

```rust
fn print_and_consume(text: String) {
    println!("{text}");
}   // здесь text уничтожается

fn main() {
    let s = String::from("привет");
    print_and_consume(s);        // владение переехало в функцию
    println!("{s}");             // ошибка: s больше не наша
}
```

Здесь то же правило: при вызове функции `s` **передаётся**, а не копируется. Внутри функции владельцем становится параметр `text`. Когда функция заканчивается — `text` уничтожается, и строка тоже.

Снаружи `s` больше не существует. Такая функция называется «поглощающей» — она забирает данные.

### Можно вернуть владение обратно

```rust
fn add_bang(mut text: String) -> String {
    text.push('!');
    text                 // возвращаем владение вызывающему
}

fn main() {
    let s = String::from("привет");
    let s = add_bang(s);              // s переехал... и вернулся, уже с "!"
    println!("{s}");                  // привет!
}
```

Здесь `let s = ...` — это **новая** переменная `s`, которая затеняет старую. Старая `s` уже не существует, потому что её владение уехало в функцию. Новая `s` владеет результатом.

Работает, но громоздко: передал — вернул — передал — вернул. Именно поэтому в Rust придумали **заимствование** — оно в следующей лекции и решает эту проблему.

## 7. Когда память освобождается

**`drop`** — автоматическое освобождение. Компилятор вставляет его в конец области видимости владельца.

```rust
fn main() {
    let s = String::from("привет");   // память выделена
    println!("{s}");
}   // ← здесь компилятор вызвал drop(s), память освобождена
```

Это и есть **время жизни значения** — от создания до конца блока, где живёт владелец.

Важно: освобождение происходит **детерминированно** — ровно в известной точке программы, а не «когда-нибудь, когда GC решит». Для программ, работающих с большими объёмами данных, это имеет значение.

## 8. Сводка: что происходит при присваивании

| Код | Тип | Что произошло | `a` дальше |
|---|---|---|---|
| `let b = a;` | `i32` | копирование | жив |
| `let b = a;` | `String` | **move** | мёртв |
| `let b = a.clone();` | `String` | копия | жив |
| `f(a)` | `i32` | копирование | жив |
| `f(a)` | `String` | **move** в функцию | мёртв |
| `f(&a)` | любой | передача ссылки (лекция 6) | жив |

## 10. Что ты теперь знаешь

- Память в куче нужно освобождать; Rust делает это без сборщика мусора и без ручного `free`.
- **`String`** — строка в куче, ею владеет переменная; `&str` — вечный текст, вшитый в программу.
- **Один владелец.** `let b = a;` для `String` — это **move**, после него `a` недоступна.
- Простые типы (`i32`, `bool`, `char`) — **`Copy`**: копируются, обе переменные живы.
- **`clone()`** — явная полная копия; применять осознанно, а не рефлекторно.
- Передача в функцию — тоже move.
- Память освобождается в конце области видимости владельца (**`drop`**).
