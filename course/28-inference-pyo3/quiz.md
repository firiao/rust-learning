# Тест к лекции 28

Ответы — в конце, под `<details>`.

## Вопросы

**1.** Зачем экспортировать модель в ONNX?

a) чтобы модель была меньше
b) ONNX — нейтральный формат: обучение в PyTorch, запуск в Rust
c) иначе Rust не поймёт тензоры

**2.** Что делает `softmax`?

a) нормализует числа в вероятности с суммой 1
b) сортирует
c) округляет до целых

**3.** Зачем вычитать максимум перед `exp`?

a) для красоты
b) чтобы `exp(1000)` не дал бесконечность: разность не меняет результат, но спасает от переполнения
c) так требует формула

**4.** Что делает `argmax`?

a) возвращает индекс максимального значения
b) сумму
c) сортирует массив

**5.** Самое частое место ошибок при переносе модели на Rust:

a) архитектура модели
b) препроцессинг: нормализация, порядок каналов, масштаб
c) выбор оптимизатора

**6.** Зачем `crate-type = ["cdylib"]` в pyo3-проекте?

a) чтобы собрать динамическую библиотеку, которую загрузит Python
b) чтобы ускорить
c) чтобы работал `cargo test`

**7.** Что обязательно должно быть в отчёте капстоуна кроме кода?

a) замеры «до/после» и объяснение выбора
b) скриншоты
c) только README

---

## Ответы

<details>
<summary>Показать</summary>

**1 — b.** Один формат, который понимают и PyTorch, и ONNX Runtime.

**2 — a.** `exp(x_i) / Σ exp(x_j)`.

**3 — b.** Численная устойчивость: `exp(1000)` — переполнение, а разности те же.

**4 — a.** Индекс максимума.

**5 — b.** Препроцессинг должен побитово совпадать с Python: забыли `/255` — модель выдаёт мусор.

**6 — a.** Python загружает `.so`.

**7 — a.** Замеры и объяснение — иначе непонятно, была ли работа осмысленной.
