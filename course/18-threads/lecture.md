# Лекция 18. Потоки

**Время:** ~30 минут

**Нужно знать заранее:** замыкания и `move`, `Rc`/`RefCell`, трейты.

**Новые слова в этой лекции:**
- **поток** — независимая «ветка» выполнения внутри одной программы;
- **`thread::spawn`** — создать поток;
- **`JoinHandle`** и **`join`** — «ручка» потока и ожидание его завершения;
- **`thread::scope`** — блок, внутри которого потоки гарантированно завершатся;
- **канал** — способ передать данные из потока в поток;
- **`mpsc`** — «много отправителей, один получатель»;
- **`Mutex`** — замок: впускает один поток за раз;
- **`Arc`** — как `Rc`, но безопасен для потоков (атомарный счётчик);
- **`Send` / `Sync`** — маркеры «можно отправить в поток» / «можно разделять между потоками».

---

## 1. Зачем потоки

Пока программы выполняли одно действие за раз. **Поток** позволяет делать несколько дел одновременно — например, обрабатывать файлы параллельно.

```rust
use std::thread;

fn main() {
    let handle = thread::spawn(|| {
        println!("привет из потока");
    });

    handle.join().unwrap();
    println!("привет из main");
}
```

Разберём:

- `thread::spawn(замыкание)` — создать поток, который выполнит замыкание;
- `handle` — **`JoinHandle`**, «ручка» потока;
- `handle.join()` — дождаться, пока поток закончит; возвращает `Result` (поток мог паниковать);
- `.unwrap()` — здесь допустимо: в учебном примере паника потока означает баг.

Без `join` главный поток может закончиться раньше, и программа завершится, не дождавшись остальных.

## 2. `move`: поток забирает данные

Замыкание потока может жить дольше функции, поэтому ссылаться на локальные переменные ему нельзя:

```rust
use std::thread;

fn main() {
    let data = vec![1, 2, 3];

    let handle = thread::spawn(move || {
        println!("{:?}", data);      // data переехал в поток
    });

    handle.join().unwrap();
    // println!("{:?}", data);       // ошибка: data больше не наш
}
```

Если убрать `move`:

```text
error[E0373]: closure may outlive the current function, but it borrows `data`
help: to force the closure to take ownership ... use the `move` keyword
```

Это ровно та же ситуация, что в лекции 15 с `make_adder`.

## 3. `thread::scope` — ссылки без `move`

Часто нужно просто **почитать** данные несколькими потоками, не забирая владение. Для этого есть `scope`:

```rust
use std::thread;

fn main() {
    let data = vec![1, 2, 3, 4];

    thread::scope(|s| {
        s.spawn(|| {
            let sum: i32 = data[..2].iter().sum();
            println!("первая половина: {sum}");
        });

        s.spawn(|| {
            let sum: i32 = data[2..].iter().sum();
            println!("вторая половина: {sum}");
        });
    });   // здесь scope ждёт все потоки

    println!("{:?}", data);   // data на месте
}
```

Почему работает без `move`: `scope` гарантирует, что все потоки завершатся **до** выхода из блока. Значит, ссылки заведомо живут достаточно долго.

Это самый удобный способ параллелить вычисления по срезу.

## 4. Каналы: передача между потоками

Потоки не должны делить память без синхронизации. Надёжнее — **передавать** данные через канал.

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    thread::spawn(move || {
        tx.send(42).unwrap();
    });

    let received = rx.recv().unwrap();
    println!("{received}");      // 42
}
```

Разберём:

- `mpsc::channel()` — создать канал; возвращает пару `(отправитель, получатель)`;
- `tx.send(значение)` — отправить; возвращает `Result` (канал мог закрыться);
- `rx.recv()` — **заблокироваться**, пока не придёт значение; возвращает `Result`.

`mpsc` расшифровывается как *multiple producer, single consumer* — «много отправителей, один получатель». Отправителей можно клонировать:

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    for i in 0..3 {
        let tx = tx.clone();
        thread::spawn(move || tx.send(i).unwrap());
    }

    drop(tx);   // важно: иначе rx будет ждать вечно

    let mut got: Vec<i32> = rx.iter().collect();
    got.sort();
    println!("{:?}", got);      // [0, 1, 2]
}
```

`drop(tx)` нужен, потому что `rx.iter()` завершается, когда уничтожены **все** отправители. Исходный `tx` остался бы жив — и цикл повис бы.

## 5. `Arc<Mutex<T>>` — общие изменяемые данные

`Rc<RefCell<T>>` (лекция 17) не работает между потоками: `Rc` не потокобезопасен, `RefCell` не синхронизирует.

Замена:

- **`Arc`** (atomic reference counting) — как `Rc`, но счётчик атомарный;
- **`Mutex`** — замок: `lock()` впускает один поток за раз.

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = Vec::new();

    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        handles.push(thread::spawn(move || {
            let mut guard = counter.lock().unwrap();
            *guard += 1;
        }));
    }

    for h in handles {
        h.join().unwrap();
    }

    println!("{}", *counter.lock().unwrap());   // 10
}
```

Разберём:

- `Arc::new(Mutex::new(0))` — счётчик, который можно менять из нескольких потоков;
- `Arc::clone(&counter)` внутри цикла — каждому потоку своя ручка;
- `counter.lock().unwrap()` — захватить замок; возвращает **`MutexGuard`**;
- `*guard += 1` — изменить значение под замком;
- guard освобождается автоматически, когда выходит из области видимости. Забыть «разлочить» невозможно.

Отсюда `10` — каждый из 10 потоков увеличил счётчик ровно на 1.

## 6. `Send` и `Sync`

Два маркерных трейта, которые проверяет компилятор:

- **`Send`** — тип можно **передать** в другой поток (`String`, `Vec`, `i32` — да; `Rc` — нет);
- **`Sync`** — тип можно **разделять** между потоками по `&T` (`Mutex<T>` — да, потому что внутри замок; `RefCell` — нет).

Их не реализуют руками. Если компилятор говорит `cannot be sent between threads safely` — значит, тип не `Send`, и это подсказка: нужен `Arc` или другая структура.

## 7. Когда потоки не нужны

- задача выполняется быстрее, чем тратится на создание потока (микросекунды);
- почти вся работа идёт под одним замком — выйдет медленнее, чем в одном потоке;
- ты ещё не измерил, что это узкое место.

Правило: **сначала однопоточно, потом измерь, потом параллель**.

## 8. Типичные ошибки

### Забыл `move`

```text
error[E0373]: closure may outlive the current function, but it borrows `data`
```

### `Rc` в потоке

```text
error[E0277]: `Rc<i32>` cannot be sent between threads safely
```

### Вечное ожидание в канале

Забыл `drop(tx)` — `rx.iter()` не завершится.

### Паника «мьютекс отравлен»

```text
error: called `Result::unwrap()` on an `Err` value: PoisonError { .. }
```

Поток запаниковал, держа замок. Данные могли остаться в несогласованном состоянии.

## 9. Что ты теперь знаешь

- `thread::spawn` + `join`; замыкание обычно с `move`.
- `thread::scope` даёт потоки с обычными ссылками и ждёт их всех.
- `mpsc` — передача данных; не забудь `drop(tx)`.
- `Arc<Mutex<T>>` — разделяемое изменяемое состояние между потоками.
- `MutexGuard` освобождает замок автоматически.
- `Send`/`Sync` проверяют безопасность на этапе компиляции.
