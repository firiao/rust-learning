# Тест к лекции 16

Ответы — в конце, под `<details>`.

## Вопросы

**1.** Что видно снаружи модуля по умолчанию?

a) всё
b) ничего: без `pub` элемент приватный
c) только функции с аргументами

**2.** Где должен лежать интеграционный тест?

a) в `src/tests.rs`
b) в `tests/*.rs`
c) в `Cargo.toml`

**3.** Что видит интеграционный тест?

a) всё, включая приватное
b) только публичный API — как внешний пользователь
c) только `main`

**4.** Зачем `#[cfg(test)]` у `mod tests`?

a) чтобы тесты запускались автоматически
b) чтобы модуль компилировался только при `cargo test`, а в обычную сборку не попадал
c) чтобы пометить тесты как `ignored`

**5.** Doc-тест — это:

a) комментарий
b) пример в `///`, который `cargo test` компилирует и запускает
c) отдельный файл

**6.** Что означает `mod geometry;` без фигурных скобок?

a) подключить `src/geometry.rs` как модуль
b) объявить пустой модуль
c) создать новый файл

**7.** Зачем `pub use geometry::area;` в `lib.rs`?

a) чтобы импортировать чужой крейт
b) чтобы пользователь вызывал `l16_modules::area`, не зная про внутренний модуль
c) чтобы сделать `area` приватной

---

## Ответы

<details>
<summary>Показать</summary>

**1 — b.** Приватность по умолчанию — обратная привычке из Java.

**2 — b.** Каждый файл в `tests/` — отдельный крейт-потребитель.

**3 — b.** Только `pub`. Если тест не может дотянуться — API слишком закрыт.

**4 — b.** Модуль вырезается из релизной сборки.

**5 — b.** Примеры в документации — часть тестов, поэтому не устаревают.

**6 — a.** `mod geometry;` ищет `src/geometry.rs` (или `src/geometry/mod.rs`).

**7 — b.** Реэкспорт: плоский публичный API при сложной внутренней структуре.

</details>
