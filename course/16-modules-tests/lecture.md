# Лекция 16. Модули, тесты и документация

**Время:** ~30 минут

**Нужно знать заранее:** всё предыдущее. Здесь собираем код в проект.

**Новые слова в этой лекции:**
- **модуль** — именованная группа кода внутри проекта;
- **`mod`** — слово, объявляющее модуль;
- **`pub`** — «видно снаружи модуля»;
- **`crate`** — весь твой проект целиком (то слово из сообщения об ошибке в лекции 1);
- **`use`** — подключить имя, чтобы не писать путь целиком;
- **unit-тест** — тест рядом с кодом, внутри модуля;
- **интеграционный тест** — тест «снаружи», проверяющий публичный API;
- **doc-тест** — пример в документации, который запускается как тест;
- **`#[test]`** — атрибут, помечающий функцию как тест;
- **`assert!`, `assert_eq!`, `assert_ne!`** — макросы проверки;
- **`clippy`** — линтер, ищет сомнительные места;
- **`fmt`** — форматтер, приводит код к официальному стилю.

## 1. Зачем модули

Один файл на 2000 строк читать невозможно. Модуль — способ разложить код по полочкам **внутри** проекта.

```rust
mod geometry {
    pub fn area(w: f64, h: f64) -> f64 {
        w * h
    }
}

fn main() {
    println!("{}", geometry::area(2.0, 3.0));   // 6
}
```

Разберём:

- `mod geometry { ... }` — **модуль** с именем `geometry` (внутри файла);
- `pub fn area` — `pub` значит «видно снаружи модуля». Без `pub` функция была бы приватной;
- `geometry::area(...)` — путь через двойное двоеточие (то же, что `String::from`).

**Приватность по умолчанию.** Всё, что не помечено `pub`, видно только внутри своего модуля. Это обратное тому, как обычно пишут в Java, где `public` ставят по привычке.

| Модификатор | Кто видит |
|---|---|
| (ничего) | только текущий модуль |
| `pub(crate)` | весь проект, но не пользователи библиотеки |
| `pub` | все |

## 2. Модуль в отдельном файле

Практичнее держать модули в файлах:

```text
src/
├── main.rs      ← корень
├── geometry.rs  ← модуль geometry
└── text.rs      ← модуль text
```

```rust
// src/main.rs
mod geometry;
mod text;

fn main() {
    println!("{}", geometry::area(2.0, 3.0));
    println!("{}", text::first_word("раз два"));
}
```

```rust
// src/geometry.rs
pub fn area(w: f64, h: f64) -> f64 {
    w * h
}
```

Правило: `mod geometry;` без фигурных скобок ищет файл `src/geometry.rs` (или `src/geometry/mod.rs`).

`use` сокращает длинные пути:

```rust
use geometry::area;

fn main() {
    println!("{}", area(2.0, 3.0));
}
```

Пути внутри проекта:

- `crate::` — корень проекта;
- `super::` — родительский модуль;
- `self::` — текущий модуль.

## 3. Unit-тесты: рядом с кодом

Тест — это обычная функция с атрибутом `#[test]`. Лежит рядом с кодом, в модуле с пометкой `#[cfg(test)]`.

```rust
pub fn area(w: f64, h: f64) -> f64 {
    w * h
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn area_of_square() {
        assert_eq!(area(2.0, 2.0), 4.0);
    }

    #[test]
    fn area_of_rectangle() {
        assert_eq!(area(3.0, 4.0), 12.0);
    }
}
```

Разберём:

- `#[cfg(test)]` — атрибут «компилировать этот модуль только при `cargo test`». В обычную сборку тесты не попадают;
- `mod tests { ... }` — просто модуль с тестами;
- `use super::*;` — «подключи всё из родительского модуля» (то есть из `geometry`), чтобы видеть `area`;
- `#[test]` — помечает функцию как тест. `cargo test` найдёт её сам, `main` для тестов не нужен;
- `assert_eq!(a, b)` — макрос: проверяет равенство и **печатает оба значения**, если не сошлось.

### Макросы проверки

```rust
assert!(condition);              // условие истинно
assert_eq!(actual, expected);    // равно
assert_ne!(a, b);                // не равно
assert!(x > 0, "x должен быть положительным, а он {x}");   // с сообщением
```

`assert_eq!` требует, чтобы тип умел `PartialEq` (лекция 11) и `Debug` (для печати при провале).

### Ещё два атрибута

```rust
#[test]
#[should_panic(expected = "делить на ноль")]
fn panics_on_zero() {
    panic!("делить на ноль нельзя");
}

#[test]
#[ignore]
fn slow_test() {
    // запускается только через cargo test -- --ignored
}
```

- `#[should_panic]` — тест **проходит**, только если случилась паника (и сообщение содержит указанное);
- `#[ignore]` — тест пропускается по умолчанию.

## 4. Интеграционные тесты: снаружи

Папка `tests/` рядом с `src/`:

```text
src/lib.rs
tests/integration.rs
```

```rust
// tests/integration.rs
use my_crate::{area, first_word};

#[test]
fn full_pipeline() {
    assert_eq!(area(2.0, 3.0), 6.0);
    assert_eq!(first_word("раз два"), "раз");
}
```

Каждый файл в `tests/` — **отдельный крейт**, который подключает твою библиотеку как внешний пользователь. Он видит только `pub`. Если тест не может дотянуться до чего-то — это сигнал: либо API слишком закрыт, либо тест лезет не туда.

## 5. Doc-тесты: примеры, которые проверяются

Пример в документации — не просто текст, а **тест**:

````rust
/// Считает площадь прямоугольника.
///
/// # Примеры
///
/// ```
/// use my_crate::area;
/// assert_eq!(area(2.0, 3.0), 6.0);
/// ```
pub fn area(w: f64, h: f64) -> f64 {
    w * h
}
````

`cargo test` компилирует и **запускает** этот пример. Значит, документация не может тихо устареть.

- `///` — документация для следующего элемента;
- `//!` — документация для всего модуля/крейта (обычно в начале файла).

---

## 6. Запуск тестов

```bash
cargo test                       # всё
cargo test area                  # только тесты, в имени которых есть "area"
cargo test --lib                 # только unit-тесты
cargo test --test integration    # только конкретный файл из tests/
cargo test --doc                 # только doc-тесты
cargo test -- --ignored          # только ignored
cargo test -- --nocapture        # показать println! из тестов
```

## 7. `clippy` и `fmt`

```bash
cargo fmt                        # отформатировать
cargo fmt -- --check             # проверить, не меняя файлы
cargo clippy                     # линтер
cargo clippy -- -D warnings      # предупреждения считать ошибками
```

### Тот самый пример с `match`

В лекции 1 был такой фрагмент — и он был непонятен, потому что `match` и `Option` там ещё не объяснялись. Теперь всё нужное есть:

```rust
match value {
    Some(x) => println!("{x}"),
    _ => {}
}
```

Расшифровка: `value` — это `Option<i32>` (лекция 9). `Some(x) => ...` — «если внутри есть число, назови его `x` и напечатай». `_ => {}` — «любой другой вариант (это `None`) — ничего не делать».

`value` — обычное перечисление с двумя вариантами. `_` — шаблон «все остальные» (лекция 8). `{}` — пустой блок, то есть «ничего».

Clippy говорит: такой `match` с одной содержательной веткой пишут короче через `if let` (лекция 9):

```rust
if let Some(x) = value {
    println!("{x}");
}
```

Смысл тот же, кода меньше. Вот и всё, что имелось в виду.

## 8. Раскладка проекта

```text
my-project/
├── Cargo.toml
├── src/
│   ├── main.rs        ← точка входа (если это программа)
│   ├── lib.rs         ← корень библиотеки
│   ├── geometry.rs    ← модуль
│   └── text.rs        ← модуль
└── tests/
    └── integration.rs ← тесты «снаружи»
```

Правило для программ: **логика — в `lib.rs` и модулях, `main.rs` — тонкая обёртка** (чтение аргументов, вызов, печать). Тогда логику можно тестировать, а `main` остаётся коротким.

## 9. Типичные ошибки

### Нет `pub`

```text
error[E0603]: function `area` is private
```

Добавь `pub` там, где функция объявлена.

### Нет файла для модуля

```text
error[E0583]: file not found for module `geometry`
```

Есть `mod geometry;`, но нет `src/geometry.rs`.

### Забыл `#[test]`

Функция в `mod tests` без `#[test]` не считается тестом и просто не запускается (будет предупреждение `function is never used`).

### Тест без `#[cfg(test)]`

Если модуль с тестами не обёрнут в `#[cfg(test)]`, тестовый код попадёт в обычную сборку — лишний вес и лишние зависимости.

## 10. Что ты теперь знаешь

- `mod` — группирует код; в отдельном файле — `mod имя;`.
- Всё приватно по умолчанию; `pub` открывает.
- `crate::`, `super::`, `self::` — пути; `use` сокращает запись.
- Unit-тесты — в `#[cfg(test)] mod tests` рядом с кодом.
- Интеграционные — в `tests/`, видят только `pub`.
- Doc-тесты — примеры в `///`, запускаются `cargo test`.
- `assert_eq!` печатает оба значения при провале.
- `cargo clippy -- -D warnings` и `cargo fmt` — минимум перед коммитом.
