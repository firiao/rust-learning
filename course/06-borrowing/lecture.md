# Лекция 6. Заимствование и borrow checker

**Время:** ~30 минут

**Нужно знать заранее:** [лекцию 5](../05-ownership/lecture.md) — владение, move, `Copy`, `clone`, `String`.

**Новые слова в этой лекции:**
- **заимствование (borrow)** — дать поработать со значением, не забирая владение;
- **ссылка** — значение, которое указывает на другие данные, но ими не владеет;
- **`&`** — «взять в долг для чтения» (неизменяемая ссылка);
- **`&mut`** — «взять в долг с правом изменения» (изменяемая ссылка);
- **borrow checker** — часть компилятора Rust, которая проверяет правила заимствования;
- **время жизни (lifetime)** — отрезок программы, пока ссылка и её данные живы;
- **срез (slice)** — ссылка на кусок данных;
- **`deref`-коэрция** — автоматическое превращение `&String` в `&str`.

---

## 1. Проблема, которую надо решить

В лекции 5 мы выяснили: если передать `String` в функцию, владение уедет внутрь, и снаружи строка станет недоступной.

```rust
fn print_len(text: String) {     // забирает владение
    println!("{}", text.len());
}

fn main() {
    let s = String::from("привет");
    print_len(s);
    println!("{s}");             // ошибка: владение уехало
}
```

Функции нужно только **посмотреть длину** — а она забирает строку целиком. Это неудобно и заставляет либо возвращать владение обратно, либо копировать через `clone()`.

Оба варианта плохи: копия — лишняя работа, возврат — лишние телодвижения.

Нужен способ **одолжить** данные на время, не отдавая их.

## 2. `&` — взять в долг для чтения

**Ссылка** — маленькое значение, которое «указывает» на другие данные. Ссылка не владеет ими, а **заимствует** их на время.

Ссылка создаётся знаком **`&`** (амперсанд):

```rust
fn print_len(text: &str) {       // принимает ссылку, не владение
    println!("{}", text.len());
}

fn main() {
    let s = String::from("привет");
    print_len(&s);               // передаём ссылку на s
    println!("{s}");             // s на месте!
}
```

Разберём:

- `&s` — «ссылка на `s`». Читается «эс по ссылке» или «амперсанд эс»;
- `text: &str` — параметр типа «ссылка на текст»;
- внутри функции `text` — это **вид** на строку `s`, а не копия;
- после вызова `s` по-прежнему наша, потому что владение не передавалось.

Параметр `text` **заимствует** строку на время выполнения функции. Когда функция заканчивается, заимствование прекращается, и `s` снова полностью наша.

### Почему `&str`, а не `&String`

Тонкость, которая многих путает.

`&s`, где `s: String`, имеет тип `&String`. Но функция принимает `&str`. Почему это работает?

Потому что Rust автоматически превращает `&String` в `&str` — это называется **`deref`-коэрция**. «Коэрция» значит «приведение», `deref` — «разыменование».

Зачем так: `&str` принимает **больше** видов текста.

```rust
fn takes(&str) { }               // псевдокод, чтобы показать смысл

let owned = String::from("abc");
takes(&owned);                   // &String -> &str автоматически
takes("abc");                    // строковый литерал — это уже &str
```

Если бы параметр был `&String`, то `takes("abc")` не скомпилировался бы: литерал `"abc"` — это `&str`, а не `&String`.

Правило: **принимай `&str`, а не `&String`**. Тогда функция примет и литерал, и `String`, и срез.

### `&str` — это тоже заимствование

Теперь понятно, что означает `&` в `&str` из лекции 2. `&str` — это «ссылка на текст». Строковые литералы `"привет"` вшиты в программу, поэтому ссылка на них безопасна всегда.

## 3. `&mut` — взять в долг с правом изменения

Хочешь не только читать, но и менять — нужна **изменяемая ссылка** `&mut`:

```rust
fn add_bang(text: &mut String) {
    text.push('!');              // меняем данные, но не владеем ими
}

fn main() {
    let mut s = String::from("привет");
    add_bang(&mut s);
    println!("{s}");             // привет!
}
```

Здесь:

- `&mut s` — «изменяемая ссылка на `s`»;
- `text: &mut String` — параметр «ссылка с правом изменения»;
- `s` объявлена как `mut`, иначе `&mut s` взять нельзя.

Обрати внимание: `&` и `&mut` — два разных типа ссылки. `&` читает, `&mut` меняет.

## 3.5. `*` — разыменование

Ссылка «смотрит» на значение, но сама значением не является. Чтобы получить то, на что она смотрит,
нужен знак **`*`** — **разыменование**:

```rust
fn main() {
    let n = 5;
    let r = &n;          // ссылка на n

    println!("{}", r);   // 5 — println! разыменовывает сам
    println!("{}", *r);  // 5 — явное разыменование
}
```

В обычном коде `*` почти не нужен: методы и `println!` разыменовывают автоматически.
Он становится важен в двух случаях:

1. **Арифметика со ссылками.** `for v in values` для среза даёт `&i32`; чтобы сложить, нужен `*v`.
2. **Изменение через `&mut`.** Запись `*a = *b` означает «запиши по адресу, на который смотрит `a`,
   значение, на которое смотрит `b`».

```rust
fn add_to(total: &mut i32, value: &i32) {
    *total += *value;    // меняем то, на что смотрит total
}

let mut sum = 10;
add_to(&mut sum, &5);
assert_eq!(sum, 15);
```

### Почему `*text.push('!')` — ошибка

Типичное заблуждение: раз `text` — ссылка, надо её «разыменовать», чтобы вызвать метод.
Получается `*text.push('!')` — и это не работает:

```text
error[E0614]: type `()` cannot be dereferenced
```

Причина в **приоритете операций**. Точечный вызов метода связывает крепче, чем унарный `*`.
Выражение разбирается так:

```text
*text.push('!')   ==   *( text.push('!') )
```

Сначала вызывается `push`, который возвращает `()`, а потом `*` пытается разыменовать `()`. Отсюда
«type `()` cannot be dereferenced».

А почему вообще методы вызываются без `*`? Потому что **методы разыменовывают сами**:
`push` объявлен как `fn push(&mut self, ch: char)`, и компилятор видит, что `text: &mut String`,
подставляет разыменование и передаёт `push` нужную ссылку. Это то же самое неявное разыменование,
которое в лекции 5 позволяло писать `text.len()`, хотя `len` объявлен для `String`.

Если очень хочется написать `*` — нужны скобки:

```rust
(*text).push('!');   // работает, но лишнее
```

Правило: **`*` нужен для значений, а не для вызовов методов**. Методы разыменовывают сами.

Запомни: `&` — «взять адрес», `*` — «пройти по адресу».

## 4. Правила заимствования

Теперь главное. Вот два правила, и всё остальное в лекции — следствия.

### Правило 1: либо много читателей, либо один писатель

В каждый момент времени для одного значения может быть **одно из двух**:

- **много** ссылок `&` (читателей), и тогда **ни одной** `&mut`;
- **ровно одна** ссылка `&mut` (писатель), и тогда **ни одной** `&`.

Иными словами: «много читающих **или** один пишущий, но не одновременно».

Аналогия с документом:

- много людей читают в Google Docs — нормально;
- один редактирует, другой в это время читает — он увидит половину правок, данные «прыгают»;
- два человека правят один абзац — конфликт.

Rust не даёт создать такую ситуацию **вообще**, ещё на этапе компиляции.

```rust
fn main() {
    let mut s = String::from("привет");

    let r1 = &s;         // читатель
    let r2 = &s;         // ещё читатель — можно
    println!("{r1} {r2}");

    let w = &mut s;      // писатель — читатели к этому моменту уже не используются
    w.push('!');
    println!("{w}");
}
```

А так — нельзя:

```rust
fn main() {
    let mut s = String::from("привет");
    let r = &s;          // читатель
    let w = &mut s;      // писатель, пока читатель жив
    println!("{r}");
    w.push('!');
}
```

```text
error[E0502]: cannot borrow `s` as mutable because it is also borrowed as immutable
 --> main.rs:4:13
  |
3 |     let r = &s;
  |             -- immutable borrow occurs here
4 |     let w = &mut s;
  |             ^^^^^^ mutable borrow occurs here
5 |     println!("{r}");
  |                - immutable borrow later used here
```

Читай по строкам ошибки: `immutable borrow occurs here` — «неизменяемое заимствование здесь»; `mutable borrow occurs here` — «изменяемое заимствование здесь»; `immutable borrow later used here` — «неизменяемое заимствование позже используется здесь» (то есть оно ещё живо).

### Правило 2: ссылка не может пережить свои данные

```rust
fn main() {
    let r;
    {
        let s = String::from("привет");
        r = &s;              // ссылка на s
    }                        // s уничтожена здесь
    println!("{r}");         // ошибка: ссылка на мёртвые данные
}
```

```text
error[E0597]: `s` does not live long enough
```

**`does not live long enough`** — «живёт недостаточно долго». Ссылка `r` хотела бы существовать дольше, чем данные `s`.

**Время жизни (lifetime)** — это отрезок программы, пока ссылка и её данные живы. Правило простое: время жизни ссылки не может быть больше времени жизни данных, на которые она указывает.

В C такая программа скомпилировалась бы и потом читала чужую память — классическая уязвимость. Rust просто не даёт её собрать.

Хорошая новость: **в 95% кода lifetimes не пишут руками**. Компилятор выводит их сам. Синтаксис с `'a` встретится позже, и только там, где без него никак (например, функция с двумя ссылками, возвращающая одну из них).

## 5. Что такое **borrow checker**

Вот и объяснение слова, которое я раньше использовал без определения.

**Borrow checker** (буквально «проверяющий заимствования») — это **часть компилятора Rust**, которая проверяет правила заимствования: правило «много читателей или один писатель» и правило «ссылка не переживает данные».

Важно понимать три вещи:

1. **Это не отдельная программа**, которую ты запускаешь. Это этап внутри `rustc`, который срабатывает при каждой сборке.
2. **Он работает до запуска программы.** Нашёл нарушение — код не компилируется, готового файла нет. Никакого «ошибка вылезла во время работы».
3. **Он ничего не добавляет в готовую программу.** Проверка целиком происходит на этапе компиляции, в машинном коде её нет. Поэтому Rust быстрый: за безопасность заплачено временем сборки, а не временем выполнения.

Как он устроен внутри, в двух словах: компилятор превращает функцию в промежуточное представление (MIR) и для каждой ссылки вычисляет, откуда она взялась и докуда живёт. Если находит одновременные `&` и `&mut` или ссылку, переживающую данные, — выдаёт ошибку `E0502`, `E0499`, `E0596` или `E0597`. Отдельный проход по коду — отсюда слово «checker».

### Почему это считается главной особенностью Rust

Потому что он ловит ошибки, которые в других языках **живут в проде годами**:

- гонки данных в многопоточных программах (в Java — `synchronized` и молитвы);
- итерация по коллекции, которую в это время меняют (в Python — `RuntimeError` во время работы, в C# — исключение);
- использование объекта после освобождения (в C++ — неопределённое поведение).

Rust ловит всё это на сборке. Цена — те самые ошибки, на которые ты сейчас смотришь. Это не придирки компилятора, а баги, которые он не дал тебе написать.

## 6. Ещё несколько ошибок заимствования

### `E0499` — два писателя

```rust
let mut s = String::from("a");
let a = &mut s;
let b = &mut s;      // второй писатель
a.push('1');
b.push('2');
```

```text
error[E0499]: cannot borrow `s` as mutable more than once at a time
```

«Нельзя взять `s` как изменяемую ссылку больше одного раза одновременно». Даже если бы это был один поток — правило всё равно действует: проще запретить всегда, чем разрешать «когда безопасно».

### `E0596` — `&mut` без `mut`

```rust
let s = String::from("a");
let r = &mut s;      // s объявлена без mut
```

```text
error[E0596]: cannot borrow `s` as mutable, as it is not declared as mutable
```

`&mut` не делает переменную изменяемой. `mut` пишется там, где переменная создаётся.

### Изменение коллекции во время перебора

Классика, которую ты уже поймёшь интуитивно, — попытка **изменить коллекцию, пока по ней идёт цикл**. Код будет таким: `for n in &collection { collection.push(...); }`.

Цикл `for` по ссылке держит ссылку на коллекцию на всё время своей работы. `push` (добавление элемента) требует изменяемую ссылку. Правило 1 запрещает держать `&` и `&mut` одновременно — значит, такой код не скомпилируется, и это правильно: иначе цикл мог бы «переехать» на перевыделенную память.

Коллекции появятся в лекции 13. Пример приведён здесь, чтобы ты **узнавал** этот тип ошибки, когда встретишь его сам.

## 7. Срезы: ссылка на кусок

**Срез (slice)** — ссылка на часть чего-то, без владения.

```rust
fn main() {
    let numbers = [10, 20, 30, 40, 50];
    let middle = &numbers[1..4];      // ссылка на элементы с 1 по 3

    for n in middle {
        println!("{n}");
    }
}
```

```text
20
30
40
```

`&numbers[1..4]` — «взять срез массива от индекса 1 до 4, не включая 4». Тип среза — `&[i32]`, читается «ссылка на срез целых».

Printf-строка `println!("{n}")` печатает **одно** значение, поэтому срез печатают циклом — то, что ты уже умеешь с лекции 4. (Для отладочной печати всей структуры в Rust есть отдельная запись `{:?}`; она требует, чтобы тип умел «отладочный вывод», и это будет в лекции про трейты. Пока обойдёмся циклом.)

### Почему `&array` подходит функции с `&[i32]`

Функция объявлена так:

```rust
fn sum(values: &[i32]) -> i32 { /* ... */ }
```

Но вызывают её с массивом:

```rust
let numbers = [10, 20, 30];
sum(&numbers);
```

Почему это работает, хотя `&numbers` — это `&[i32; 3]`, а не `&[i32]`?

Потому что Rust **сам превращает ссылку на массив в ссылку на его элементы**. Это называется
**приведение массива к срезу** (array-to-slice coercion): `&[i32; 3]` → `&[i32]`.

То же самое с куском массива:

```rust
sum(&numbers[1..3]);   // &numbers[1..3] уже имеет тип &[i32]
```

Практический вывод: **функция с параметром `&[T]` принимает и массив, и его кусок, и `Vec<T>`
(о нём позже)**. Поэтому такие параметры пишут почти всегда, когда нужна последовательность.

Создавать срез вручную не надо — это делает либо `&array`, либо `&array[..]`, и делает это
**вызывающий**, а не функция.

### Срезы строк

Строку тоже можно резать:

```rust
fn main() {
    let text = "привет, мир";
    let hello = &text[0..12];         // "привет"

    println!("{hello}");
}
```

Но здесь важная ловушка: **индексы срезов строк считаются в байтах, а не в символах**.

Буквы кириллицы в UTF-8 занимают по 2 байта. Слово «привет» — это 6 символов, но 12 байт. Поэтому `&text[0..12]` даёт «привет», а `&text[0..6]` даёт только «при» — и это ещё повезло, что граница попала на границу символа.

```rust
let text = "привет";
let bad = &text[0..3];   // паника: индекс 3 — середина буквы
```

```text
thread 'main' panicked at main.rs:3:20:
end byte index 3 is not a char boundary; it is inside 'р' (bytes 2..4 of string)
```

`not a char boundary` — «не граница символа», а дальше компилятор даже показывает, внутри какой буквы оказался разрез.

Вывод: **не режь строки по числовым индексам, если не уверен в границах**. Для текста используют методы, которые ходят по символам: `chars()` и `char_indices()` (второй разбирается в разделе 7.5).

Запомни, насколько это отличается от Python: там `"привет"[0:3]` спокойно даёт `"при"`, потому что Python индексирует символы. В Rust `len()` и индексы — про байты.

## 7.5. Возвращаем срез: первое слово

Самое практичное применение заимствований — **вернуть кусок входных данных, не копируя их**.
Классический пример: первое слово строки.

```rust
fn first_word(text: &str) -> &str {
    for (i, ch) in text.char_indices() {
        if ch == ' ' {
            return &text[..i];
        }
    }
    text
}

fn main() {
    println!("{}", first_word("привет мир"));   // привет
    println!("{}", first_word("привет"));       // привет
}
```

Разберём по частям.

**`text.char_indices()`** — новый метод. Он перебирает строку и даёт пары:

```text
(0, 'п'), (2, 'р'), (4, 'и'), (6, 'в'), (8, 'е'), (10, 'т'), (12, ' ')
```

**Первое число — байтовый индекс символа.** Именно в байтах, а не в символах: кириллическая буква
занимает 2 байта, поэтому индексы идут `0, 2, 4, …`. Это прямое следствие того, что строка в Rust —
это UTF-8 (лекция 2).

Зачем такой метод: `&text[..i]` режет **байты**. Если бы мы считали символы и писали `&text[..3]`,
для «привет» это разрезало бы букву «р» пополам, и программа упала бы с
`byte index 3 is not a char boundary`. `char_indices` всегда даёт индексы на границах символов.

**`return &text[..i];`** — возвращаем **срез исходной строки**: указатель внутрь неё плюс длина.
Никакого копирования.

**`text` в конце** — если пробела не нашлось, всё слово целиком тоже является срезом.

Почему компилятор разрешает вернуть ссылку: у функции **один** входной параметр-ссылка, поэтому
результат привязывается к нему (правило из раздела 6). Функция `fn f(a: &str, b: &str) -> &str`
так не может — там непонятно, от кого из двух зависит результат.

### Пробелы бывают разные

`ch == ' '` ловит только обычный пробел. Но между словами может стоять **табуляция** (`\t`) или
**перевод строки** (`\n`), и тогда проверка на `' '` их пропустит.

В стандартной библиотеке есть два помощника:

```rust
ch.is_whitespace()      // true для пробела, таба, перевода строки и т.п.
text.trim()             // срез без пробелов по краям (возвращает &str)
```

`trim()` возвращает **срез**, а не новую строку, — поэтому он бесплатный.

Практическое правило: если задача про «слова», проверяй `is_whitespace()`, а не `' '`.
И помни: между словами может быть **несколько** пробелов подряд — тогда простой подсчёт
«количество пробелов + 1» даёт неверный ответ.

**Что это даёт на практике:** функция, которая возвращает `String`, копирует данные всегда.
Функция, возвращающая `&str`-срез, не копирует ничего — она просто говорит «вот кусок твоей же
строки». Для больших текстов это разница в разы.

## 8. Итоговая таблица: три способа передать данные

| Способ | Запись | Что даёт | Владение | Можно менять |
|---|---|---|---|---|
| по значению | `f(s)` | передаёт | уезжает внутрь | — |
| по ссылке | `f(&s)` | читает | остаётся у тебя | нет |
| по изменяемой ссылке | `f(&mut s)` | читает и меняет | остаётся у тебя | да |

Три правила, которые надо помнить:

1. `&` — читать, `&mut` — менять.
2. Много `&` **или** один `&mut`. Не одновременно.
3. Ссылка не живёт дольше своих данных.

## 9. Что ты теперь знаешь

- **Заимствование** — дать поработать с данными, не забирая владение.
- `&` — ссылка для чтения, `&mut` — ссылка с правом изменения.
- Много `&` **или** один `&mut` одновременно.
- Ссылка не может пережить данные, на которые указывает (`E0597`).
- **Borrow checker** — этап компилятора, который проверяет эти правила до запуска программы. В готовом коде его нет.
- Принимай `&str`, а не `&String`: deref-коэрция превратит `&String` в `&str` автоматически.
- Срез — ссылка на часть данных; индексы строк считаются в байтах.
- `char_indices()` даёт пары (байтовый индекс, символ) — так безопасно резать текст.
- Функция может вернуть срез входных данных, если ссылка-параметр одна.
