# Лаба 6. Заимствование

## Четыре функции

### 1. `last_word(text: &str) -> &str` — **последнее** слово

`"привет мир"` → `"мир"`. `"привет"` → `"привет"`. `""` → `""`.

Слово начинается сразу после **последнего** пробела, поэтому `"привет "` → `""` (пустое слово после
пробела) — это проверяется отдельным тестом.

**Это не копия примера из лекции.** В лекции 6 разобран `first_word`, который останавливается
на **первом** пробеле и выходит из цикла досрочно. Здесь наоборот: надо пройти строку **целиком**
и запомнить, где кончался последний пробел. Приём тот же (`char_indices`), а программа другая.

**Чему учит:** срез может начинаться не с нуля, а с любого места строки.

### 2. `push_bang(text: &mut String)` — дописать `!` на месте

Владение остаётся у вызывающего: `&mut String` вместо `String`.

Сравни с лабой 5:

```rust
fn append_bang(mut text: String) -> String   // владение уехало и вернулось
fn push_bang(text: &mut String)              // владение не уезжало вообще

a = append_bang(a);   // присваивание обязательно
push_bang(&mut a);    // a уже наш
```

#### Почему `*text.push('!')` не работает

Ты написал `*text.push('!')` — и это правильное ожидание, но Rust разбирает выражение иначе.
**Точечный вызов метода связывает крепче унарного `*`:**

```text
*text.push('!')   ==   *( text.push('!') )
```

Сначала вызывается `push`, он возвращает `()` — и `*` пытается разыменовать пустое значение:

```text
error[E0614]: type `()` cannot be dereferenced
```

А почему методы вообще вызываются без `*`? Потому что **методы разыменовывают сами**:
`push` объявлен как `fn push(&mut self, ch: char)`, компилятор видит `text: &mut String`
и подставляет нужную ссылку сам. Это то же неявное разыменование, что в лабе 5 позволяло писать
`text.len()`.

Если очень хочется явный `*` — нужны скобки: `(*text).push('!')`. Работает, но лишнее.

**Правило: `*` нужен для значений, а не для вызовов методов.**

### 3. `sum_slice(values: &[i32]) -> i32` — сумма готового среза

Что значит «срез создаёт вызывающий»: у функции в параметре написано `&[i32]` — это **уже ссылка
на последовательность**. Функция её не строит и не копирует, она только читает.

Срез создаётся **в месте вызова**, тремя способами:

```rust
let array = [1, 2, 3];

sum_slice(&array);        // 1) ссылка на весь массив
sum_slice(&array[0..2]);  // 2) ссылка на кусок массива
sum_slice(&[]);           // 3) пустой массив
```

Почему `&array` подходит, хотя это `&[i32; 3]`, а не `&[i32]`: Rust **сам** превращает ссылку
на массив в ссылку на его элементы (`&[i32; 3]` → `&[i32]`). Это называется приведением массива
к срезу и разобрано в лекции 6, раздел 7.

**Чему учит:** функция с параметром `&[T]` принимает и массив, и кусок массива, и (позже) `Vec`.

### 4. `count_char(text: &str, target: char) -> usize` — сколько раз символ встречается

Цикл по `chars()` (символы, а не байты) и сравнение с `target`.

## Подсказки

<details>
<summary>`last_word` — если застрял</summary>

```rust
let mut start = 0;
for (i, ch) in text.char_indices() {
    if ch == ' ' {
        start = i + 1;      // следующий символ идёт после пробела
    }
}
&text[start..]
```

`char_indices()` возвращает пары: байтовый индекс символа и сам символ. Пробел занимает 1 байт,
поэтому `i + 1` — корректная граница следующего символа.

Почему это не копия `first_word`: там `return &text[..i]` внутри цикла (выход на первом пробеле),
здесь цикл идёт до конца, а `start` запоминает **последнюю** позицию.

</details>

<details>
<summary>`push_bang`</summary>

```rust
text.push('!');
```

Без `*` и без скобок: метод разыменовывает сам.

</details>

<details>
<summary>`sum_slice`</summary>

```rust
let mut total = 0;
for v in values {
    total += *v;      // v: &i32
}
total
```

`for v in values` по срезу даёт **ссылки** на элементы. Здесь `*` нужен: `v` — значение-ссылка,
а `+=` работает с числом. Это ровно тот случай, где `*` уместен.

</details>
