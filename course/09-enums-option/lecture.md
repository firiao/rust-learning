# Лекция 9. Перечисления и `Option`

**Время:** ~30 минут

**Нужно знать заранее:** `struct`, `impl`, методы, `match` с шаблонами и `_`, `if`.

**Новые слова в этой лекции:**
- **перечисление (`enum`)** — тип, значение которого является **одним из** нескольких вариантов;
- **вариант** — один из возможных случаев перечисления;
- **`Option<T>`** — перечисление «значение есть или его нет»: `Some(значение)` или `None`;
- **`Some`** — вариант «есть значение»;
- **`None`** — вариант «значения нет»;
- **`if let`** — короткая форма `match`, когда интересен только один вариант.

---

## 1. Задача: значение — «одно из»

Обычная структура всегда содержит **все** свои поля. Но часто значение бывает «одним из нескольких разных вещей»:

- фигура — это круг **или** прямоугольник **или** треугольник;
- результат операции — успех **или** ошибка;
- возраст пользователя — число **или** «не указан».

Для таких случаев есть **`enum`** (сокращение от *enumeration*, «перечисление»).

---

## 2. Простое перечисление

Начнём с самого простого: перечисление без данных.

```rust
#[derive(Debug, PartialEq)]
enum Color {
    Red,
    Green,
    Blue,
}
```

Разберём:

- `enum` — слово, объявляющее перечисление;
- `Color` — имя нового типа;
- `Red`, `Green`, `Blue` — **варианты**. Возможных значений ровно три, и других быть не может.

Создаются значения так:

```rust
let c = Color::Red;
```

`Color::Red` — «вариант `Red` перечисления `Color`». То же двойное двоеточие, что в `String::from` и `Product::new`: путь внутри типа.

Сравнивать можно благодаря `#[derive(PartialEq)]` (лекция 7):

```rust
fn main() {
    let c = Color::Red;

    if c == Color::Red {
        println!("красный");
    }
}
```

Для простых перечислений `if` хватает. Но как только вариантов больше двух и у них есть данные, `if` становится неудобным — и тут пригодится `match` из лекции 8.

---

## 3. Перечисление с данными

Главное отличие от Java и Python: **каждый вариант может нести свои данные**, причём разные.

```rust
#[derive(Debug)]
enum Shape {
    Circle { radius: f64 },
    Rectangle { width: f64, height: f64 },
    Empty,
}
```

Разберём:

- `Circle { radius: f64 }` — вариант «круг», у которого есть поле `radius`;
- `Rectangle { width: f64, height: f64 }` — вариант «прямоугольник» с двумя полями;
- `Empty` — вариант без данных.

Обрати внимание: варианты **разные по структуре**. У `Circle` одно число, у `Rectangle` два. Это не «класс с полями», а именно «одно из»: значение типа `Shape` — это **или** круг, **или** прямоугольник, **или** пусто. Никогда два сразу.

Создание:

```rust
let a = Shape::Circle { radius: 2.0 };
let b = Shape::Rectangle { width: 3.0, height: 4.0 };
let c = Shape::Empty;
```

---

## 4. `match` по перечислению

Вот где `enum` раскрывается. `match` умеет не только сравнивать, но и **доставать данные** из варианта:

```rust
fn area(shape: &Shape) -> f64 {
    match shape {
        Shape::Circle { radius } => std::f64::consts::PI * radius * radius,
        Shape::Rectangle { width, height } => width * height,
        Shape::Empty => 0.0,
    }
}
```

Разберём:

- `match shape` — сопоставляем значение `shape` с вариантами;
- `Shape::Circle { radius }` — **шаблон**: «если это круг, достань его поле `radius` в переменную `radius`»;
- `Shape::Rectangle { width, height }` — «если прямоугольник, достань два поля»;
- `Shape::Empty => 0.0` — «если пусто, верни 0».

Все три варианта перечислены. **`_` не нужен**, потому что вариантов ровно три и они все покрыты.

`std::f64::consts::PI` — константа «число π». Читается по частям: `std` — стандартная библиотека, `f64` — тип, `consts` — раздел констант, `PI` — сама константа.

### Что будет, если забыть вариант

```rust
match shape {
    Shape::Circle { radius } => 3.14 * radius * radius,
    Shape::Rectangle { width, height } => width * height,
}
```

```text
error[E0004]: non-exhaustive patterns: `Shape::Empty` not covered
```

Компилятор **называет** пропущенный вариант. Именно за это `match` по `enum` так ценят: добавил в перечисление новый вариант — компилятор покажет все места в программе, где его нужно обработать. Забыть невозможно.

Для сравнения: в Python ты бы узнал об этом только когда программа дошла бы до этого места и упала.

## 5. `Option<T>` — «значение или ничего»

Теперь всё готово, чтобы понять самый важный `enum` в Rust. Он есть в стандартной библиотеке и выглядит так:

```rust
enum Option<T> {
    Some(T),
    None,
}
```

Разберём:

- `Option` — имя типа;
- `<T>` — «параметр типа»: `Option` может хранить значение **любого** типа. `Option<i32>` — «число или ничего», `Option<String>` — «строка или ничего». Подробно обобщения будут в лекции 12; сейчас достаточно читать `<T>` как «какой-то тип»;
- `Some(T)` — вариант «есть значение типа `T`»;
- `None` — вариант «значения нет».

Это буквально обычное перечисление с двумя вариантами. Никакой магии.

Создание:

```rust
let a: Option<i32> = Some(42);
let b: Option<i32> = None;
```

### Зачем это нужно

В Python и Java любое значение может оказаться «пустым»: `None` в Python, `null` в Java. Проблема в том, что **это не видно в типе**. Функция вернула строку — а может ли она вернуть `null`? Никто не знает, пока не упадёт.

В Rust «может не быть» — это **отдельный тип**. Если функция возвращает `Option<i32>`, ты обязан обработать оба случая, и компилятор это проверит.

Сравни:

```text
Python:  def find(...) -> int          # может вернуть None, но тип этого не говорит
Rust:    fn find(...) -> Option<usize> # тип прямо говорит: может не быть
```

### Как достать значение

Через `match`:

```rust
fn find_first_even(values: &[i32]) -> Option<usize> {
    for (i, v) in values.iter().enumerate() {
        if *v % 2 == 0 {
            return Some(i);
        }
    }
    None
}

fn main() {
    let values = [1, 3, 4, 6];

    match find_first_even(&values) {
        Some(index) => println!("первое чётное на позиции {index}"),
        None => println!("чётных нет"),
    }
}
```

Что здесь новое:

- `values: &[i32]` — «ссылка на срез чисел» (срез из лекции 6, массив из лекции 4);
- `values.iter().enumerate()` — перебор с индексами. `iter()` — «взять итератор по элементам», `enumerate()` — «добавить номер». Подробно итераторы будут в лекции 14; здесь достаточно смысла «перебрать пары (индекс, значение)»;
- `*v` — разыменование: `v` имеет тип `&i32` (ссылка), а сравнивать нужно число, поэтому `*v` даёт `i32`.

Если тебе этот цикл пока не нравится — это нормально. Важен результат: функция возвращает `Option<usize>` — либо `Some(индекс)`, либо `None`.

## 6. `if let` — когда интересен один вариант

Часто нужен только один вариант, а второй — «ничего не делать». Тогда `match` с пустой веткой получается громоздким:

```rust
match find_first_even(&values) {
    Some(index) => println!("нашли {index}"),
    None => {}                       // ничего не делаем
}
```

Для этого есть короткая форма — **`if let`**:

```rust
if let Some(index) = find_first_even(&values) {
    println!("нашли {index}");
}
```

Читается буквально: «если значение подходит под шаблон `Some(index)` — выполни блок». Если не подошло — просто идём дальше.

`if let` — это `match` с одним рукавом и пустым `_`. Смысл тот же, запись короче.

Есть и `while let` — цикл «пока подходит шаблон». Он понадобится позже; запись такая: `while let Some(x) = ... { }`.

## 7. Полезные методы `Option`

Кроме `match` и `if let`, у `Option` есть готовые методы. Это методы (лекция 7), поэтому вызываются через точку:

```rust
let maybe: Option<i32> = Some(5);

maybe.is_some();            // true  — «значение есть»
maybe.is_none();            // false — «значения нет»
maybe.unwrap_or(0);         // 5     — «значение или 0, если нет»
maybe.unwrap_or_default();  // 5     — «значение или значение по умолчанию»
```

`unwrap()` без аргументов — **опасный**:

```rust
let nothing: Option<i32> = None;
println!("{}", nothing.unwrap());
```

```text
thread 'main' panicked at:
called `Option::unwrap()` on a `None` value
```

`unwrap` говорит: «я уверен, что значение есть». Если ошибся — программа аварийно завершается (**паника**). В учебных тестах это допустимо, в библиотечном коде — почти никогда.

---

## 8. Типичные ошибки

### Пропущен вариант в `match`

```text
error[E0004]: non-exhaustive patterns: `Shape::Empty` not covered
```

Добавь рукав для пропущенного варианта.

### `unwrap` на `None`

```text
thread 'main' panicked at: called `Option::unwrap()` on a `None` value
```

Не используй `unwrap`, если `None` возможен. Возьми `match`, `if let` или `unwrap_or`.

### Забыл, что тип — `Option`

```rust
let x: Option<i32> = Some(5);
let y = x + 1;      // нельзя: x — это не число, а «число или ничего»
```

```text
error[E0369]: cannot add `{integer}` to `Option<i32>`
```

Сначала нужно **достать** число из `Option`, потом с ним работать. Это не придирка: компилятор не даёт забыть про случай «значения нет».

---

## 9. Что ты теперь знаешь

- `enum` — тип, значение которого является **одним из** вариантов.
- Варианты могут нести разные данные или не нести ничего.
- `match` по `enum` достаёт данные из варианта и обязан покрыть все варианты.
- `Option<T>` — стандартное перечисление `Some(T)` / `None`.
- `Option` делает «может не быть» видимым в типе, в отличие от `null`/`None`.
- `if let` — короткая форма `match` для одного варианта.
- `unwrap()` на `None` — паника; безопаснее `unwrap_or` или `match`.
