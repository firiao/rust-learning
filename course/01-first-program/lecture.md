# Лекция 1. Как текст превращается в программу

**Время:** ~20 минут

**Новые слова в этой лекции:**
- **исходный код** — текст программы, который пишет человек;
- **компилятор** — программа, которая переводит исходный код в машинный;
- **скомпилировать** — перевести исходный код в машинный;
- **собрать** — скомпилировать все части программы и соединить в один файл;
- **запустить** — попросить операционную систему выполнить готовый файл;
- **функция** — именованный кусок кода, который можно выполнить;
- **`main`** — функция, с которой начинается любая программа;
- **строка** (в смысле текста) — последовательность символов в кавычках;
- **макрос** — команда компилятору, которая во время компиляции разворачивается в обычный код;
- **`println!`** — макрос, который печатает текст в консоль;
- **точка с запятой** — знак, который завершает команду (как точка в предложении);
- **комментарий** — текст в коде, который компилятор не читает.

---

## 1. Два вида текста

Процессор понимает только последовательности чисел — машинные команды. Человек их писать не может: в одной строке будет что-то вроде `10110000 01100001`, и понять это глазами невозможно.

Поэтому программы пишут на **исходном коде** — тексте, понятном человеку, — а переводит его в машинные команды специальная программа. Есть три способа это делать.

**Интерпретатор** (Python): специальная программа читает исходный код и тут же выполняет его. Перевод и выполнение происходят одновременно, строка за строкой. Поэтому Python такой медленный — на каждый запуск он заново разбирает текст.

**Компилятор** (Rust, C, C++): специальная программа **заранее** переводит весь исходный код в машинные команды и сохраняет их в файл. Потом этот файл запускается без всякого переводчика. Поэтому Rust такой быстрый — процессор сразу получает готовые команды.

**Промежуточный вариант** (Java): компилятор переводит код не в машинный, а в «универсальный» байткод, который потом выполняет виртуальная машина JVM. Уже почти машинный код, но ему всё равно нужен переводчик на месте.

| | Python | Java | Rust |
|---|---|---|---|
| Перевод в машинный код | при каждом запуске | при сборке, но не в машинный | при сборке, в машинный |
| Что нужно для запуска | интерпретатор Python | JVM | ничего |
| Скорость | медленно | быстро | быстро |

«Нужно ничего» — это буквально. В Rust готовая программа — один файл, который запускается на такой же машине без установки чего-либо ещё.

## 2. Три слова: скомпилировать, собрать, запустить

Это три разных шага, которые часто путают. Разберём на твоей машине.

### Скомпилировать

Компилятор Rust называется **`rustc`**. Он берёт один файл `.rs` и делает из него готовый к запуску файл.

Что происходит внутри:

```text
main.rs          ← исходный код, текст
   │
   │  1. компилятор читает текст и проверяет, правильно ли он написан
   │
   ▼
машинные команды ← последовательность чисел, которую понимает процессор
   │
   │  2. компилятор упаковывает их в файл вместе с данными (например, с текстом)
   ▼
hello            ← обычный файл-программа, его можно запускать
```

Для программы «напечатай привет» это занимает около **0,07 секунды**, а готовый файл весит примерно **445 КБ**. Кажется много для одной строчки, но туда вложен весь код печати текста, который Rust даёт тебе сразу.

### Собрать

Слово **«собрать»** (от англ. *build*) — шире, чем «скомпилировать».

Реальная программа состоит не из одного файла: твой код + части стандартной библиотеки Rust + чужие библиотеки, которые ты подключил. Каждую из них нужно скомпилировать, а потом **соединить** результаты в один файл. Соединение называется **линковкой**.

```text
твой код ─скомпилировать─┐
стандартная библиотека ──┼─ слинковать ──►  одна готовая программа
чужие библиотеки ────────┘
```

В Rust «собрать» делает инструмент **`cargo`** — он сам вызывает `rustc` нужное число раз. Поэтому:

- **скомпилировать** — это работа `rustc` над одним куском кода;
- **собрать** — это работа `cargo` надо всем проектом целиком, включая соединение.

### Запустить

**Запустить** — значит попросить операционную систему выполнить готовый файл. Операционная система загружает его в память, находит там функцию `main` и начинает выполнять команды одну за другой.

Компилятор и cargo в запуске уже не участвуют. Готовая программа работает сама.

## 3. Первая программа и её построчный разбор

Вот самая маленькая программа на Rust, которая что-то делает:

```rust
fn main() {
    println!("Привет");
}
```

Выглядит коротко, но здесь **девять** незнакомых вещей. Разберём каждую.

### `fn` — объявление функции

```rust
fn
```

`fn` — сокращение от английского *function* («функция»). Это слово говорит компилятору: «сейчас я опишу функцию, а не что-то другое».

Функция — это именованный кусок кода. Части функции:

```rust
fn  имя  (что принимает)  {  что делает  }
```

### `main` — имя, которое особенное

```rust
fn main
```

`main` — просто имя функции. Но с этим именем связан договор: когда ты запускаешь программу, операционная система ищет функцию именно с таким названием и начинает выполнение с неё.

Это называется **точка входа**.

- В Python программа начинается с первой строки файла.
- В Java — с метода `public static void main(String[] args)`.
- В Rust — с функции `main`. Всегда.

Если функции `main` нет, компилятор откажется создавать программу:

```text
error[E0601]: `main` function not found in crate `hello`
```

`crate` здесь — «единица компиляции», грубо говоря проект; подробно это слово разберём в лекции 14. Смысл сообщения: «в проекте `hello` не нашлась функция `main`».

### `()` после имени — что функция принимает

```rust
fn main()
```

Круглые скобки — это место для того, что функция получает на вход. В скобках у `main` пусто, значит она ничего не получает.

Сравни с Python: `def greet(name):` — там в скобках `name`, функция получает имя. Здесь скобки пустые: `main` не принимает ничего.

Подробно про то, что может быть в скобках, — в лекции 3.

### `{ }` — тело функции

```rust
fn main() {
    println!("Привет");
}
```

Фигурные скобки — это «тело»: всё, что находится между ними, будет выполнено, когда функцию вызовут.

У `main` тело — одна строка. Она и выполнится при запуске программы.

Отступ внутри скобок (четыре пробела) ничего не значит для компилятора — он нужен людям, чтобы видеть структуру. Но форматируй так всегда: так принято, и по-другому твой код никто не будет читать.

### `println!` — печать текста

```rust
println!("Привет");
```

Это тот самый вывод в консоль. Разберём по частям.

**`println`** — от *print line*, «напечатай строку». Это команда «выведи текст в консоль и перейди на новую строку».

**`!`** сразу после имени — знак того, что `println!` — **макрос**, а не обычная функция.

Что такое макрос, по-простому: это команда **компилятору**, которая **во время компиляции** разворачивается в обычный код. Без восклицательного знака `println` была бы обычной функцией, и ей нельзя было бы красиво передать текст с заменой частей — только строку целиком. С `!` компилятор сам собирает нужный код под конкретное содержимое.

**Важно не перепутать:** макрос — это не отдельная программа и не «предварительная компиляция». Он **разворачивается внутри той же сборки**: компилятор читает твой файл, встречает `println!(...)`, подставляет вместо него готовый код и только потом проверяет типы. Отдельного шага «сначала скомпилировать макрос» нет.

Проверить это можно самому. Если объявить макрос с бессмысленным телом, но **не вызывать** его — программа соберётся:

```rust
macro_rules! bad {
    () => { это вообще не Rust };   // пока не используется — компилятор не смотрит внутрь
}

fn main() {
    println!("программа собралась");
}
```

```text
warning: unused macro definition: `bad`
программа собралась
```

А если вызвать `bad!();` — ошибка появится, и компилятор укажет, что она «произошла в этом вызове макроса». Значит, макрос не компилируется заранее: он **разворачивается в точке вызова**, и уже развёрнутый код проверяется.

**Почему нельзя было сделать обычную функцию?** Функция получает аргументы, которые уже вычислены, и их число и типы фиксированы при её описании. А `println!` должен принимать **любое** число аргументов **любых** типов: `println!("{x}")`, `println!("{a} {b}")`, `println!("{}", 5)` — и превращать это в один кусок кода для вывода. Функция так не умеет: её аргументы должны быть известны заранее. Макрос умеет, потому что работает **до** компиляции и может «собрать» нужный вызов под конкретную строку.

Правило простое: **`println!` всегда пишется с `!`**. Встретишь имя с `!` — это макрос. Писать свои макросы ты будешь позже, а читать чужие — постоянно.

**`"Привет"`** — **строка**, текст в двойных кавычках. Именно текст, а не код: компилятор не пытается понять слово «Привет», он просто сохраняет эти буквы в программе.

Кавычки обязательно **двойные**. В Python одинарные и двойные равноценны, в Rust — нет: в одинарных кавычках может стоять **ровно один символ**, например `'a'`. Если написать `'Привет'`, компилятор скажет:

```text
error: character literal may only contain one codepoint
help: if you meant to write a string literal, use double quotes
```

`character literal` — «символьный литерал», то есть один символ. Такие типы (`'a'`) будут в лекции 2; пока достаточно знать: **много букв — только в двойных кавычках**.

**`;`** в конце — **точка с запятой**. Она завершает команду, как точка завершает предложение. Почти каждая команда в Rust кончается на `;`.

Забыть `;` — самая частая ошибка у новичков. Компилятор скажет что-то вроде `expected ';'` и покажет, где не хватает.

### Что получится

```text
$ cargo run
Привет
```

Программа напечатала текст и завершилась.

## 4. Комментарии

**Комментарий** — текст в коде, который компилятор не читает. Он для людей.

```rust
// Это комментарий. Компилятор его игнорирует.
fn main() {
    println!("Привет"); // можно и в конце строки
}
```

Две косые черты `//` — начало комментария. Всё до конца строки — не код.

В Python это `#`, в Java и Rust — `//`.

Комментарии нужны не для «что делает код» (это видно из кода), а для «почему так сделано». Например: `// 0.01 подобрано экспериментально, больше — расходится`.

## 5. Как это запустить

Для одного файла можно было бы вызывать компилятор напрямую, но в Rust так не делают. Используют **`cargo`** — инструмент, который создаёт проект и запускает сборку.

> **Новое слово: `cargo`** — менеджер проектов Rust. Он создаёт папку проекта, собирает код и запускает программу. Подробно — в отдельной лекции; сейчас нужно три команды.

```bash
cargo new hello          # создать проект в папке hello
cd hello                 # зайти в него
cargo run                # собрать и запустить
```

Что создастся:

```text
hello/
├── Cargo.toml     ← описание проекта (имя, версия, зависимости)
└── src/
    └── main.rs    ← сюда пишешь код
```

`Cargo.toml` — текстовый файл, который описывает проект. Можешь открыть и посмотреть, но менять пока не нужно.

`src/main.rs` — файл, в который кладут программу. `src/` — сокращение от *source*, «исходники».

Порядок работы такой:

1. `cargo new hello` — один раз.
2. Правишь `src/main.rs`.
3. `cargo run` — собрать и запустить.

Слово `run` здесь означает «собрать, если нужно, и запустить». Поэтому отдельно писать `cargo build` и потом искать файл не надо.

## 6. Что будет, если ошибиться

Компилятор не просто говорит «ошибка». Он показывает **где** и **что делать**. Два примера, чтобы ты не испугался, когда увидишь их сам.

### Забыл точку с запятой

```rust
fn main() {
    println!("первая")
    println!("вторая");
}
```

```text
error: expected `;`, found `println`
 --> main.rs:2:23
  |
2 |     println!("первая")
  |                       ^ help: add `;` here
3 |     println!("вторая");
  |     ------- unexpected token
```

Читается так: «ожидал точку с запятой, а нашёл `println`». Компилятор даже ставит стрелку `^` в то место, где не хватает `;`, и пишет `help: add `;` here` — то есть «добавь сюда точку с запятой».

Заметь: ошибка указывает на **конец** предыдущей строки, а не на следующую. Это нормально — компилятор понял, что команда не закончилась, но только на следующей строке.

### Забыл `!` у `println!`

```rust
fn main() {
    println("Привет");
}
```

```text
error[E0423]: cannot find function `println` in this scope
 --> main.rs:2:5
  |
2 |     println("Привет");
  |     ^^^^^^^ not found in this scope
  |
  = note: a macro named `println` exists in another namespace
help: use `!` to invoke the macro
  |
2 |     println!("Привет");
  |            +
```

Разберём по строкам:

- `cannot find function 'println'` — «не нахожу функции `println`»;
- `note: a macro named 'println' exists in another namespace` — «но есть макрос с таким именем»;
- `help: use '!' to invoke the macro` — «добавь `!`, чтобы вызвать макрос»;
- `+` в последней строке показывает, **куда** его вставить.

**Всегда читай строки, начинающиеся с `help:`** — в них обычно и лежит ответ.

Обрати внимание на `E0423` — это номер ошибки. По нему в терминале можно получить подробное объяснение:

```bash
rustc --explain E0423
```

Полезная привычка: увидел непонятный код ошибки — посмотри объяснение, а не ищи форум.

> Почему в первом примере ошибка сработала, а если убрать `;` в **последней** строке функции — нет? Потому что последняя строка в функции значит немного другое. Это разберём в лекции 3, когда дойдём до «выражений».

## 7. Что ты теперь знаешь

- Программа на Rust — это текст, который **компилятор** переводит в машинные команды заранее.
- **Скомпилировать** — перевести один кусок кода. **Собрать** — скомпилировать всё и соединить в один файл. **Запустить** — выполнить готовый файл.
- Выполнение начинается с функции `main`.
- `fn` объявляет функцию, `{ }` — её тело.
- `println!("текст")` печатает текст; `!` означает макрос.
- Строки — в двойных кавычках.
- Команды заканчиваются `;`.
- `//` — комментарий.
- `cargo new` создаёт проект, `cargo run` собирает и запускает.
