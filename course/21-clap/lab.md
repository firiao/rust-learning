## Цель

Научиться разбирать аргументы так, чтобы разбор можно было **протестировать**.

## В крейте только спека

`practice/l21-*` содержит **только тесты** — файл `tests/spec.rs`. Никаких структур, функций
и заготовок с `todo!()` там нет: всё пишешь ты.

**Тесты — это и есть ТЗ.** В них видно:

- как называются функции и типы;
- какие у них аргументы и что они возвращают;
- какое поведение считается правильным (это и есть требования).

Открывай `tests/spec.rs` и начинай с первого теста. Пока код не написан, `cargo test -p <пакет>`
не компилируется — это нормально, спека ещё не выполнена.

```bash
cargo test -p l21-clap    # сначала ошибки компиляции, потом красные тесты
```

## Реализуй

**`parse_args(items: &[&str]) -> Result<Args, clap::Error>`** — разобрать аргументы и вернуть
заполненную структуру `Args`, либо ошибку `clap`, если аргументы некорректны.

Почему обёртка, а не `Args::parse()` напрямую: `parse()` при ошибке завершает процесс, а такое
не протестируешь. `try_parse_from` возвращает `Result` — его можно проверить в тесте.

Важно: `items` **не содержит** имени программы (`"file.txt"` идёт первым), а `clap` ожидает
имя первым элементом. Значит, его надо подставить самому — иначе `clap` примет `"file.txt"`
за имя программы и скажет, что не хватает `PATH`.

## Дополнительное задание — проектируешь сам

Добавь в `Args` флаг `--verbose` (`bool`) и позиционный аргумент `--limit` с проверкой диапазона.

Тест напиши сам: без флага, с флагом, с неверным значением.

Запиши в `NOTES.md`, почему выбрал такую сигнатуру или такой тип.

## Критерии приёмки

- [ ] 5 тестов зелёные;
- [ ] `parse_args(&[])` и `parse_args(&["--top","5"])` дают `Err` (нет обязательного `path`);
- [ ] `clippy -D warnings` и `fmt --check` чистые после реализации;
- [ ] в `NOTES.md` объяснено, зачем имя программы и как выглядит `--help`.

## Подсказки

<details>
<summary>Реализация</summary>

```rust
pub fn parse_args(items: &[&str]) -> Result<Args, clap::Error> {
    let mut full = vec!["prog"];
    full.extend_from_slice(items);
    Args::try_parse_from(full)
}
```

`"prog"` — любое имя; оно попадёт в строку `Usage:` в сообщениях об ошибках.

</details>

<details>
<summary>Как выглядит `main.rs` для такой программы</summary>

```rust
use clap::Parser;
use l21_clap::Args;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let args = Args::parse();
    let text = std::fs::read_to_string(&args.path)?;
    println!("строк: {}", text.lines().count());
    let _ = args.top;
    Ok(())
}
```

`Args::parse()` — то же, что `try_parse_from`, но при ошибке печатает сообщение и завершает процесс
с кодом 2.

</details>

<details>
<summary>Почему у `clap` первым идёт имя программы</summary>

Это наследие C: `argv[0]` — имя исполняемого файла. `clap` использует его в `Usage:`.

В реальной программе `std::env::args()` уже включает `argv[0]`, поэтому там подставлять ничего
не нужно — сложность только в тестах, где список аргументов задаёшь ты сам.

</details>
