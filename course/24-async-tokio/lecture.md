# Лекция 24. async и tokio

**Время:** ~30 минут

**Нужно знать заранее:** потоки (лекция 18), замыкания, `Result`.

**Новые слова в этой лекции:**
- **`async`** — пометка «эта функция может приостанавливаться»;
- **`Future`** — «обещание результата, который появится позже»;
- **`.await`** — «подожди, пока это будущее завершится»;
- **runtime (исполнитель)** — то, что двигает задачи вперёд;
- **`tokio`** — самый популярный runtime для Rust;
- **задача (`task`)** — как поток, но легче: тысячи на одной ОС-поток;
- **`tokio::spawn`** — запустить задачу.

---

## 1. Задача, которую решают async

Потоки (лекция 18) стоят дорого: каждый — это поток операционной системы, память под стек, переключение контекста. Для 10 000 одновременных сетевых соединений это слишком.

При этом в сети программа **почти всё время ждёт**: ответа сервера, данных из сокета. Ждать в отдельном потоке — расточительство.

`async` позволяет писать код «как будто последовательный», но во время ожидания исполнитель переключается на другую задачу.

## 2. `async fn` и `.await`

```rust
async fn fetch_value() -> i32 {
    42
}

#[tokio::main]
async fn main() {
    let value = fetch_value().await;
    println!("{value}");      // 42
}
```

Разберём:

- `async fn` — возвращает не `i32`, а **`Future`**, который когда-нибудь даст `i32`;
- **ничего не выполняется**, пока не появится `.await`;
- `.await` — «дождись результата и дай значение»;
- `#[tokio::main]` — атрибут, который превращает обычный `main` в async-`main` и поднимает runtime.

`Future` — это трейт из стандартной библиотеки (лекция 11). `async fn` — сахар: компилятор сам пишет структуру, реализующую `Future`.

### Почему `.await` обязателен

```rust
let f = fetch_value();     // Future, но НИЧЕГО не выполнилось
println!("{f:?}");         // ошибка: у Future нет Debug
let v = f.await;           // вот теперь выполнилось
```

Это как итераторы (лекция 14): описание работы без запуска.

## 3. `tokio`: runtime и задачи

```bash
cargo add tokio --features full
```

```toml
[dependencies]
tokio = { version = "1", features = ["full"] }
```

`full` включает всё: runtime, макросы, таймеры, каналы. Для учебного проекта это нормально; в продакшене обычно включают конкретные features (лекция 19).

### Несколько задач одновременно

```rust
use std::time::Duration;

#[tokio::main]
async fn main() {
    let a = tokio::spawn(async {
        tokio::time::sleep(Duration::from_millis(50)).await;
        "первая"
    });

    let b = tokio::spawn(async {
        tokio::time::sleep(Duration::from_millis(10)).await;
        "вторая"
    });

    println!("{}", b.await.unwrap());   // вторая (быстрее)
    println!("{}", a.await.unwrap());   // первая
}
```

Разберём:

- `tokio::spawn(...)` — запустить задачу, вернуть `JoinHandle` (как `thread::spawn`);
- `tokio::time::sleep(...)` — асинхронная пауза. `.await` отдаёт управление другим задачам;
- `handle.await` — дождаться результата. `unwrap()` — задача могла запаниковать.

Обе задачи стартуют сразу. `b` завершится раньше, потому что спит меньше. Итог: сначала «вторая», потом «первая».

### Сравнение с потоками

| | Потоки (`thread`) | Задачи (`tokio`) |
|---|---|---|
| Что стоит дорого | создание и стек | почти ничего |
| Сколько можно | сотни | десятки тысяч |
| Переключение | делает ОС | делает runtime |
| Хорошо для | вычислений | ввода-вывода |

Правило: **много ожидания сети/диска — async; тяжёлые вычисления — потоки**.

## 4. `join!` и `try_join!`

```rust
use std::time::Duration;

async fn work(name: &str, ms: u64) -> String {
    tokio::time::sleep(Duration::from_millis(ms)).await;
    format!("{name} готов")
}

#[tokio::main]
async fn main() {
    let (a, b) = tokio::join!(
        work("раз", 30),
        work("два", 10),
    );
    println!("{a}, {b}");
}
```

`tokio::join!` запускает все будущие параллельно и ждёт **все**. `try_join!` — то же, но останавливается на первой ошибке.

Обрати внимание: `join!` — **макрос**, а не метод. Он принимает переменное число будущих — то, чего не может обычная функция (лекция 23).

## 5. Асинхронные каналы

Похоже на `mpsc` из лекции 18, но `.await` вместо блокировки:

```rust
use tokio::sync::mpsc;

#[tokio::main]
async fn main() {
    let (tx, mut rx) = mpsc::channel(8);

    tokio::spawn(async move {
        for i in 0..3 {
            tx.send(i).await.unwrap();
        }
    });

    while let Some(v) = rx.recv().await {
        println!("{v}");
    }
}
```

- `mpsc::channel(8)` — канал ёмкостью 8 (у tokio канал ограничен по размеру);
- `tx.send(i).await` — отправка может подождать, если канал полон;
- `rx.recv().await` — ожидание значения; `None`, когда все отправители ушли.

`while let Some(v) = ...` — тот же паттерн из лекции 9.

## 6. Осторожности

**1. `.await` нельзя в обычной функции.**

```text
error[E0728]: `await` is only allowed inside `async` functions and blocks
```

**2. `std::sync::Mutex` в async-коде — ловушка.** Держать обычный мьютекс во время `.await` нельзя: задача может уйти на простой, не отпустив замок. Используй `tokio::sync::Mutex` или, чаще, вообще не деля состояние.

**3. Async — не про скорость счёта.** `async` ускоряет ожидание ввода-вывода, а не вычисления.

**4. Не смешивай два runtime.** Если проект на `tokio`, всё должно быть на `tokio`.

## 7. Типичные ошибки

### Забыл `.await`

```rust
async fn f() -> i32 { 1 }
fn main() {
    let x = f();          // x: Future<i32>, а не i32
}
```

```text
error[E0308]: mismatched types
expected `i32`, found opaque type `impl Future<Output = i32>`
```

### `spawn` требует `'static`

```text
error[E0521]: borrowed data escapes outside of closure
```

Задача может жить дольше функции, поэтому забирай данные через `move` или клонируй `Arc`.

### Блокирующий вызов внутри async

`std::thread::sleep` внутри async-задачи останавливает весь поток исполнителя. Используй `tokio::time::sleep`.

---

## 8. Что ты теперь знаешь

- `async fn` возвращает `Future`; без `.await` ничего не выполняется.
- `#[tokio::main]` поднимает runtime.
- `tokio::spawn` — лёгкая задача; `handle.await` — дождаться.
- `tokio::join!` ждёт все будущие параллельно.
- Асинхронные каналы — `tokio::sync::mpsc`, с `.await`.
- Async — для ожидания ввода-вывода, потоки — для вычислений.
