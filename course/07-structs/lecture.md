# Лекция 7. Структуры и методы

**Время:** ~25 минут

**Нужно знать заранее:** `let`, `mut`, типы, функции (`fn`, `->`), области видимости, `String` и владение.

**Новые слова в этой лекции:**
- **структура (`struct`)** — свой тип, который объединяет несколько значений под одним именем;
- **поле** — одно из значений внутри структуры;
- **экземпляр** — конкретное значение структуры, созданное по её описанию;
- **`impl`** — блок, в котором пишут методы для типа;
- **метод** — функция, привязанная к типу и вызываемая через точку;
- **`self`** — «тот экземпляр, у которого вызвали метод»;
- **ассоциированная функция** — функция внутри `impl`, но без `self`; вызывается через `Тип::имя`;
- **`#[derive(...)]`** — просьба к компилятору сгенерировать стандартные реализации;
- **`Debug`** — «умение печататься для отладки»; даёт запись `{:?}`.

---

## 1. Зачем нужна структура

До этого мы хранили по одному значению в переменной. Реальные объекты — это **набор** связанных значений: у точки есть `x` и `y`, у товара — название, цена и количество.

Можно завести три отдельные переменные:

```rust
let product_name = "ноутбук";
let product_price = 75000.0;
let product_count = 3;
```

Проблема: ничто не говорит, что эти три переменные — про один товар. Передашь функцию — придётся передавать три аргумента. Забудешь один — ошибка.

**Структура** объединяет значения в один тип с одним именем.

---

## 2. Описание структуры

```rust
struct Product {
    name: String,
    price: f64,
    count: u32,
}
```

Разберём:

- `struct` — слово, которое объявляет структуру (от англ. *structure*, «структура»);
- `Product` — имя нового типа. Стиль Rust: имена типов с большой буквы;
- `{ ... }` — **поля**: имя поля, двоеточие, тип;
- `name: String`, `price: f64`, `count: u32` — три поля.

Это **описание**, а не значение. Оно говорит: «`Product` — это три вещи: строка, дробное число и целое без знака». Память при этом ещё не выделяется.

---

## 3. Создание значения (экземпляра)

Конкретное значение структуры называется **экземпляром**.

```rust
fn main() {
    let laptop = Product {
        name: String::from("ноутбук"),
        price: 75000.0,
        count: 3,
    };

    println!("{}", laptop.name);
    println!("{}", laptop.price);
    println!("{}", laptop.count);
}
```

Разберём:

- `Product { ... }` — создание экземпляра. Имя типа и в фигурных скобках значения полей;
- `name: String::from("ноутбук")` — «полю `name` присвоить вот это значение»;
- `laptop` — переменная, которая **владеет** всей структурой (владение из лекции 5);
- `laptop.name` — доступ к полю через точку. Читается «лаптоп, поле name».

**Все поля обязательны.** Пропустишь — компилятор скажет:

```text
error[E0063]: missing field `price` in initializer of `Product`
```

Это сделано специально: компилятор гарантирует, что структура никогда не окажется «полупустой». Вспомни, зачем это нужно, — в лекции 8 будет `Option`, и там станет понятно, почему «пустоты» лучше не допускать.

### Сокращённая запись

Если переменная называется так же, как поле, можно не повторяться:

```rust
let name = String::from("ноутбук");
let price = 75000.0;
let count = 3;

let laptop = Product { name, price, count };   // то же, что name: name и т.д.
```

Это просто сокращение записи, никакой магии.

## 4. Методы: поведение структуры

Данные — только половина. Вторая половина — что с ними можно делать.

В Rust данные и поведение **пишут раздельно**. Поведение — в блоке **`impl`** (от англ. *implementation*, «реализация»).

```rust
impl Product {
    fn total(&self) -> f64 {
        self.price * self.count as f64
    }
}
```

Разберём:

- `impl Product { ... }` — «здесь поведение для типа `Product`»;
- `fn total(&self) -> f64` — функция внутри `impl`. Из-за первого параметра `&self` она становится **методом**;
- **`self`** — это «тот экземпляр, у которого метод вызвали». Внутри метода `self` — как `laptop` снаружи.

Вызов:

```rust
fn main() {
    let laptop = Product {
        name: String::from("ноутбук"),
        price: 75000.0,
        count: 3,
    };

    println!("{}", laptop.total());
}
```

`laptop.total()` — «выполни у `laptop` метод `total`». Внутри метода `self` будет равен `laptop`.

### Три вида `self`

Первый параметр метода определяет, что метод может делать с экземпляром. Это те же три способа передать данные из лекций 5–6.

| Запись | Что означает | Можно ли менять | Владение |
|---|---|---|---|
| `&self` | «одолжи экземпляр почитать» | нет | остаётся у вызывающего |
| `&mut self` | «одолжи с правом изменения» | да | остаётся у вызывающего |
| `self` | «забери экземпляр» | — | переходит методу |

```rust
impl Product {
    // читает
    fn total(&self) -> f64 {
        self.price * self.count as f64
    }

    // меняет
    fn add_stock(&mut self, extra: u32) {
        self.count = self.count + extra;
    }

    // забирает владение и превращает в другой тип
    fn into_name(self) -> String {
        self.name
    }
}
```

Обрати внимание:

- `add_stock(&mut self, ...)` — чтобы вызвать, переменная должна быть `mut` (как в лекции 2);
- `into_name(self)` — забирает `Product`; после вызова исходная переменная недоступна. Так делают, когда метод «превращает» значение во что-то другое.

`as f64` в `self.count as f64` — **приведение типа**. `count` имеет тип `u32` (целое), а `price` — `f64` (дробное). Умножать разные типы нельзя, поэтому `u32` превращают в `f64` записью `значение as тип`.

## 5. Ассоциированные функции и `::`

Функция внутри `impl` **без** `self` называется **ассоциированной функцией**. Она не имеет отношения к конкретному экземпляру — она относится к типу целиком.

```rust
impl Product {
    // без self — вызывается через Product::new(...)
    fn new(name: &str, price: f64, count: u32) -> Self {
        Product {
            name: String::from(name),
            price,
            count,
        }
    }
}
```

- `Self` (с большой буквы) — «тип, внутри `impl` которого мы находимся», то есть `Product`;
- `fn new(...)` — ассоциированная функция, потому что первым параметром не идёт `self`;
- вызов: `Product::new("ноутбук", 75000.0, 3)`.

Вот теперь окончательно понятно двойное двоеточие `::` из лекции 5: **`Тип::имя` — «взять имя внутри типа»**. `String::from(...)` — это ассоциированная функция `from` внутри типа `String`, ровно как `Product::new`.

Соглашение: функцию `new`, которая создаёт значение, называют именно `new`. Это не волшебное слово, просто договорённость.

## 6. `derive`: сгенерировать стандартное поведение

Некоторые поведения настолько предсказуемы, что компилятор может написать их сам. Просят об этом атрибутом **`#[derive(...)]`** (от англ. *derive*, «выводить»).

```rust
#[derive(Debug, Clone, PartialEq)]
struct Product {
    name: String,
    price: f64,
    count: u32,
}
```

Что даёт каждая:

| Что просим | Что получаем |
|---|---|
| `Debug` | возможность печатать структуру для отладки через `{:?}` |
| `Clone` | метод `.clone()` — полная копия (лекция 5) |
| `PartialEq` | сравнение `==` и `!=` |

### `Debug` и запись `{:?}`

Без `Debug` структуру нельзя напечатать вообще:

```rust
let laptop = Product { ... };
println!("{laptop}");
```

```text
error[E0277]: `Product` doesn't implement `std::fmt::Display`
```

Компилятор говорит: «не знаю, как тебя печатать». Есть два способа печати:

- `{}` — «красивый, для пользователя» (тип должен уметь `Display`);
- `{:?}` — «отладочный, для программиста» (тип должен уметь `Debug`).

Знак вопроса внутри скобок и переключает способ. `Debug` можно получить через `#[derive(Debug)]`, а `Display` — только написать руками (компилятор не знает, как ты хочешь видеть товар в отчёте).

```rust
#[derive(Debug)]
struct Product {
    name: String,
}

fn main() {
    let p = Product { name: String::from("ноутбук") };
    println!("{p:?}");    // Product { name: "ноутбук" }
}
```

`Debug` печатает имя типа и все поля. Если нажать по-другому — `{p:#?}` — выведет каждое поле на отдельной строке (полезно для больших структур).

Теперь запись `{:?}`, которую мы обошли в лекции 6, объяснена полностью: это отладочная печать, и она требует, чтобы тип умел `Debug`.

## 7. Пример целиком

```rust
#[derive(Debug, Clone, PartialEq)]
struct Point {
    x: f64,
    y: f64,
}

impl Point {
    fn new(x: f64, y: f64) -> Self {
        Self { x, y }
    }

    fn distance_to(&self, other: &Point) -> f64 {
        let dx = self.x - other.x;
        let dy = self.y - other.y;
        (dx * dx + dy * dy).sqrt()
    }
}

fn main() {
    let a = Point::new(0.0, 0.0);
    let b = Point::new(3.0, 4.0);

    println!("{}", a.distance_to(&b));   // 5
    println!("{a:?}");                   // Point { x: 0.0, y: 0.0 }
}
```

Разбор:

- `Self { x, y }` — сокращённая запись создания (поля названы как параметры);
- `distance_to(&self, other: &Point)` — метод, который берёт себя для чтения и **ссылку** на другую точку. Ссылку, а не владение, потому что точка `b` нам нужна после вызова;
- `.sqrt()` — метод числа `f64` («квадратный корень»). Методы есть не только у наших типов;
- `{a:?}` — отладочная печать, работает благодаря `#[derive(Debug)]`.

## 8. Типичные ошибки

### Забыл поле

```text
error[E0063]: missing field `price` in initializer of `Product`
```

Нужно указать все поля.

### Опечатка в имени поля

```text
error[E0560]: struct `Product` has no field named `prise`
```

Компилятор даже подсказывает похожее имя: `help: a field with a similar name exists: 'price'`.

### Метод меняет, а переменная не `mut`

```rust
let laptop = Product::new("ноутбук", 1.0, 1);
laptop.add_stock(5);
```

```text
error[E0596]: cannot borrow `laptop` as mutable, as it is not declared as mutable
```

`add_stock(&mut self)` требует `mut`-переменную.

### Нет `Debug`

```text
error[E0277]: `Product` doesn't implement `Debug`
```

Добавь `#[derive(Debug)]`.

---

## 9. Что ты теперь знаешь

- `struct` объединяет поля в новый тип; при создании указывают **все** поля.
- `impl` — блок поведения для типа.
- Метод — это функция с `self`; вызывается через точку.
- `&self` — читать, `&mut self` — менять, `self` — забрать.
- Ассоциированная функция — без `self`, вызывается `Тип::имя`; двойное двоеточие — путь внутри типа.
- `#[derive(Debug, Clone, PartialEq)]` — сгенерировать стандартные поведения.
- `{:?}` — отладочная печать, требует `Debug`.
