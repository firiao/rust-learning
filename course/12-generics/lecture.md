# Лекция 12. Обобщения (generics)

**Время:** ~25 минут

**Нужно знать заранее:** функции, трейты, `impl … for`, `Option`/`Result`.

**Новые слова в этой лекции:**
- **обобщение (generic)** — код, который работает не с одним типом, а с любым подходящим;
- **параметр типа** — `<T>` в описании функции или структуры: «какой-то тип, назовём его `T`»;
- **ограничение (bound)** — `T: Trait`, «`T` обязан уметь то, что требует трейт»;
- **мономорфизация** — превращение обобщённого кода в отдельную версию для каждого конкретного типа;
- **`impl Trait`** — короткая запись «принимаю/возвращаю что-то, реализующее трейт»;
- **`where`** — способ вынести ограничения после сигнатуры, чтобы она не распухла.

---

## 1. Задача: один алгоритм — разные типы

Допустим, нужна функция «найти самое большое число в списке». Для `i32`:

```rust
fn largest_i32(values: &[i32]) -> Option<i32> {
    let mut best = values[0];
    for &v in &values[1..] {
        if v > best {
            best = v;
        }
    }
    Some(best)
}
```

Для `f64` — та же логика, с другим типом:

```rust
fn largest_f64(values: &[f64]) -> Option<f64> {
    let mut best = values[0];
    for &v in &values[1..] {
        if v > best {
            best = v;
        }
    }
    Some(best)
}
```

Тело одинаковое. Копировать его для каждого типа — плохо. **Обобщение** позволяет написать один раз.

> Срезы `&[i32]` мы видели в лекции 6, `Option` — в лекции 9. Здесь в примерах есть ещё `values[0]` и `&values[1..]` — «первый элемент» и «срез без первого». Это обычное индексирование, подробнее в лекции 13.

---

## 2. Параметр типа `<T>`

```rust
fn largest<T: PartialOrd + Copy>(values: &[T]) -> Option<T> {
    let mut best = values[0];
    for &v in &values[1..] {
        if v > best {
            best = v;
        }
    }
    Some(best)
}
```

Разберём `fn largest<T: PartialOrd + Copy>`:

- `<T: ...>` — **параметр типа**. Читается «для какого-то типа, который назовём `T`»;
- `:` после `T` — «который обязан уметь»;
- `PartialOrd` — трейт «умеет сравниваться через `<`, `>`, `<=`, `>=`»;
- `+` — «и ещё»;
- `Copy` — трейт «копируется, а не перемещается» (лекция 5).

Целиком: «для любого типа `T`, который умеет сравниваться и копироваться».

Вызов — как обычной функцией, тип выводится сам:

```rust
fn main() {
    println!("{:?}", largest(&[3, 7, 2]));        // Some(7)
    println!("{:?}", largest(&[1.5, 0.5]));       // Some(1.5)
    println!("{:?}", largest(&['я', 'б']));       // Some('я')
}
```

Одна функция — три типа. Компилятор подставил `T = i32`, потом `T = f64`, потом `T = char`.

`{:?}` — отладочная печать (лекция 7), здесь чтобы напечатать `Option`.

## 3. Почему ограничения обязательны

Можно попробовать без ограничений:

```rust
fn largest<T>(values: &[T]) -> Option<T> {
    let mut best = values[0];
    for &v in &values[1..] {
        if v > best {        // сравнение
            best = v;
        }
    }
    Some(best)
}
```

```text
error[E0369]: binary operation `>` cannot be applied to type `T`
help: consider restricting type parameter `T` with trait `PartialOrd`
```

Компилятор объясняет: «операцию `>` нельзя применить к типу `T`» — потому что не всякий тип умеет сравниваться. Он даже подсказывает, какое ограничение добавить.

Это принципиально: **обобщённый код может делать с `T` только то, что разрешено ограничениями**. Никаких «а вдруг у него есть нужный метод» — проверяется заранее.

С `Copy` та же история: строка `let mut best = values[0];` копирует элемент из среза. Если `T` не `Copy`, это было бы перемещение из чужого среза, что запрещено (лекция 5).

## 4. Несколько параметров типа

```rust
fn make_pair<A, B>(first: A, second: B) -> (A, B) {
    (first, second)
}

fn main() {
    let p = make_pair(1, "один");
    println!("{:?}", p);      // (1, "один")
}
```

`<A, B>` — два независимых параметра типа. Здесь ограничений нет, потому что функция ничего с ними не делает, кроме упаковки в кортеж.

## 5. Обобщённые структуры

Параметр типа может быть у структуры:

```rust
#[derive(Debug)]
struct Pair<T> {
    first: T,
    second: T,
}

fn main() {
    let ints = Pair { first: 1, second: 2 };
    let text = Pair { first: "а", second: "б" };
    println!("{:?} {:?}", ints, text);
}
```

`Pair<T>` — «пара значений одного типа `T`». `Pair<i32>` и `Pair<&str>` — **разные типы**, но описание одно.

### Методы у обобщённой структуры

```rust
impl<T: PartialOrd> Pair<T> {
    fn larger(&self) -> &T {
        if self.first > self.second {
            &self.first
        } else {
            &self.second
        }
    }
}
```

Разберём:

- `impl<T: PartialOrd> Pair<T>` — «методы для `Pair` с любым `T`, который умеет сравниваться»;
- `fn larger(&self) -> &T` — возвращает **ссылку** на большее значение, а не копию. Так работает для любого `T`, даже если он не `Copy`;
- `&self.first` — ссылка на поле.

Можно писать `impl Pair<i32>` — тогда методы будут только для `Pair<i32>`. Но чаще пишут обобщённо.

## 6. Обобщённые перечисления — ты их уже знаешь

`Option<T>` и `Result<T, E>` из лекций 9–10 — это ровно то же самое:

```rust
enum Option<T> {
    Some(T),
    None,
}

enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

Когда ты пишешь `Option<i32>`, ты подставляешь `T = i32`. Всё, что было в лекциях 9–10, — это использование обобщений, просто без объяснения слова.

---

## 7. `impl Trait` — короткая запись

Вместо `<T: Shape>` в параметре можно написать:

```rust
fn print_area(shape: &impl Shape) {
    println!("{}", shape.area());
}
```

Это то же самое, что `fn print_area<T: Shape>(shape: &T)`. Удобно, когда параметр один и ограничение одно.

В **возвращаемом** типе `impl Trait` значит другое: «возвращается какой-то тип, реализующий трейт, но какой именно — не твоё дело»:

```rust
fn make_circle() -> impl Shape {
    Circle { radius: 1.0 }
}
```

Зачем: чтобы можно было вернуть «что угодно, умеющее Shape», не называя конкретный тип. Внутри должна быть **одна** конкретная реализация (нельзя вернуть то `Circle`, то `Square` в зависимости от условия — для этого нужен `dyn`).

---

## 8. `where` — ограничения отдельно

Если ограничений много, сигнатура становится нечитаемой. Тогда их выносят:

```rust
fn print_all<T>(items: &[T])
where
    T: std::fmt::Debug + Clone,
{
    for item in items {
        println!("{:?}", item);
    }
}
```

`where` — то же самое, что ограничения в `<...>`, только ниже и с переносами. Читается легче, когда ограничений три и больше.

---

## 9. Мономорфизация: почему это быстро

**Мономорфизация** — компилятор создаёт **отдельную копию** функции для каждого конкретного типа, с которым её вызвали.

```text
largest::<i32>   — своя машинная версия
largest::<f64>   — своя
largest::<char>  — своя
```

Последствия:

- **скорость**: вызов прямой, никакой таблицы методов и проверок в рантайме — как если бы ты написал три функции руками;
- **размер**: бинарник растёт, если типов много;
- **время сборки**: растёт по той же причине.

Сравни с Java: там обобщения «стираются» — в рантайме `List<Integer>` и `List<String>` одинаковы, а скорость платит приведением типов. В Rust платят размером бинарника, но получают скорость.

## 10. Типичные ошибки

### Нет нужного ограничения

```text
error[E0369]: binary operation `>` cannot be applied to type `T`
help: consider restricting type parameter `T` with trait `PartialOrd`
```

Добавь `T: PartialOrd` (или `+` ещё что-то).

### Слишком сильное ограничение

```rust
fn count<T: Copy>(items: &[T]) -> usize {
    items.len()
}
```

Компилятор предупредит: `Copy` не используется. Ограничение сужает круг типов без пользы.

### `impl Trait` в возврате с двумя разными типами

```rust
fn pick(flag: bool) -> impl Shape {
    if flag {
        Circle { radius: 1.0 }     // разные типы
    } else {
        Square { side: 1.0 }
    }
}
```

```text
error[E0308]: `if` and `else` have incompatible types
```

`impl Shape` — это **один** конкретный тип, спрятанный от вызывающего. Для «то или другое» нужен `Box<dyn Shape>` (лекция 11).

---

## 11. Что ты теперь знаешь

- Обобщение — один код для многих типов: `<T>`.
- Ограничение `T: Trait` говорит, что с `T` можно делать.
- Обобщёнными бывают функции, структуры, перечисления (`Option`, `Result`).
- `impl Trait` — короткая запись в параметре; в возврате означает «один скрытый тип».
- `where` — ограничения после сигнатуры.
- Мономорфизация: скорость как у ручного кода, ценой размера бинарника.
