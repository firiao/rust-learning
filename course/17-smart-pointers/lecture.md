# Лекция 17. Умные указатели и время жизни

**Время:** ~30 минут

**Нужно знать заранее:** владение, заимствование, трейты, обобщения.

**Новые слова в этой лекции:**
- **умный указатель** — значение, которое владеет данными в куче и освобождает их по своим правилам;
- **`Box<T>`** — «данные в куче, владелец один»;
- **`Rc<T>`** — «данные в куче, владельцев несколько» (счётчик ссылок);
- **счётчик ссылок** — число владельцев `Rc`; данные живут, пока он больше нуля;
- **`RefCell<T>`** — «проверка заимствований во время выполнения, а не при компиляции»;
- **интерьерная изменяемость** — возможность менять данные через неизменяемую ссылку;
- **время жизни ссылки (lifetime)** — отрезок программы, пока ссылка и её данные живы;
- **`'static`** — метка «живёт всю программу».

---

## 1. `Box<T>` — просто «положи в кучу»

Умный указатель — это значение, которое **владеет** данными (как `String` владеет текстом) и освобождает их при выходе из области видимости (лекция 5).

Самый простой — `Box` (от англ. *box*, «коробка»):

```rust
fn main() {
    let boxed: Box<i32> = Box::new(42);
    println!("{}", boxed);        // 42 — работает как обычное число
}
```

`Box::new(42)` кладёт число в кучу и возвращает владельца. Зачем, если `i32` и так маленький?

### Главная причина: рекурсивные типы

```rust
enum List {
    Cons(i32, Box<List>),
    Nil,
}
```

Без `Box` компилятор откажется:

```text
error[E0072]: recursive type `List` has infinite size
help: insert some indirection (e.g., a `Box`, `Rc`, or `&`) to break the cycle
```

Почему: `List` содержит `List`, размер не вычислить — он бесконечен. `Box<List>` — указатель фиксированного размера, проблема снята.

Проверь руками:

```rust
fn main() {
    let list = List::Cons(1, Box::new(List::Cons(2, Box::new(List::Nil))));
    println!("{:?}", list);
}
```

`Box` — единственный владелец. Никакой магии, просто «данные в куче, адрес на стеке».

---

## 2. `Rc<T>` — несколько владельцев

Иногда данные нужны сразу нескольким владельцам: дерево с общими узлами, кеш, разделяемая конфигурация.

```rust
use std::rc::Rc;

fn main() {
    let a = Rc::new(String::from("общие данные"));
    let b = Rc::clone(&a);
    let c = Rc::clone(&a);

    println!("{}", Rc::strong_count(&a));   // 3

    drop(a);
    println!("{}", Rc::strong_count(&b));   // 2
}
```

Разберём:

- `Rc::new(...)` — создать владельца в куче;
- `Rc::clone(&a)` — **не копия данных**, а новый владелец тех же данных: счётчик увеличился на 1. Поэтому пишут `Rc::clone(&a)`, а не `a.clone()` — так видно, что это дешёвая операция;
- `Rc::strong_count(&a)` — сколько сейчас владельцев;
- `drop(a)` — «пусть `a` умрёт»; счётчик уменьшается.

Данные освобождаются, когда счётчик падает до нуля.

**Важно:** `Rc` не потокобезопасен. Он не реализует `Send`, поэтому отправить его в другой поток нельзя. Для потоков — `Arc` (лекция 18).

## 3. `RefCell<T>` — проверка заимствований в рантайме

Правила лекции 6 (много `&` **или** один `&mut`) проверяются компилятором. Иногда статически доказать безопасность не получается — например, когда структура данных ссылается сама на себя.

`RefCell` переносит эту проверку **в время выполнения**:

```rust
use std::cell::RefCell;

fn main() {
    let cell = RefCell::new(5);

    *cell.borrow_mut() += 1;
    println!("{}", cell.borrow());     // 6
}
```

- `cell` не объявлен `mut` (он и не должен), но значение внутри меняется — это и есть **интерьерная изменяемость**;
- `borrow()` — «взять почитать», возвращает умный указатель на данные;
- `borrow_mut()` — «взять с правом изменения».

Плата: нарушение правил теперь **паника**, а не ошибка компиляции:

```rust
let cell = RefCell::new(5);
let a = cell.borrow();
let b = cell.borrow_mut();
```

```text
thread 'main' panicked at: already borrowed: BorrowMutError
```

Компилятор такое не поймает: для него `borrow()` и `borrow_mut()` — обычные методы.

Правило: держи заимствования короткими (в одну строку) и не используй `RefCell` без необходимости.

---

## 4. `Rc<RefCell<T>>` — общий изменяемый объект

Комбинация, которая встречается постоянно: несколько владельцев **и** возможность менять.

```rust
use std::cell::RefCell;
use std::rc::Rc;

fn main() {
    let log = Rc::new(RefCell::new(Vec::new()));

    let l1 = Rc::clone(&log);
    let l2 = Rc::clone(&log);

    l1.borrow_mut().push("первая запись");
    l2.borrow_mut().push("вторая запись");

    println!("{:?}", log.borrow());
    println!("{}", Rc::strong_count(&log));   // 3
}
```

`Rc` даёт общее владение, `RefCell` — право менять. Вместе — аналог обычного объекта из Python или Java.

Минусы: паника вместо ошибки компиляции и не работает между потоками.

---

## 5. Что выбрать

| Задача | Инструмент |
|---|---|
| Данные в куче, один владелец | `Box<T>` |
| Рекурсивная структура (список, дерево) | `Box<T>` |
| Несколько владельцев в одном потоке | `Rc<T>` |
| Менять через общую ссылку | `RefCell<T>` |
| И то и другое | `Rc<RefCell<T>>` |
| Несколько потоков | `Arc<Mutex<T>>` (лекция 18) |

Правило: **сначала попробуй обычное владение**. В большинстве кода `Rc<RefCell<_>>` не нужен; если он понадобился — присмотрись к структуре данных.

## 6. Время жизни ссылок (lifetime)

В лекции 6 мы говорили: «ссылка не может жить дольше данных». Это и есть **время жизни**.

Компилятор вычисляет его сам почти всегда — поэтому ты редко видишь этот синтаксис. Но две вещи нужно понимать.

### `'static` — «живёт всю программу»

```rust
fn name(&self) -> &'static str {
    "круг"
}
```

`'static` (читается «статик») — метка: данные живут всё время работы программы. Строковые литералы `"круг"` вшиты в бинарник, поэтому они `'static`.

Когда ты видишь `&'static str` — это значит «ссылка на текст, который никогда не освободится». Чаще всего это литерал.

### Когда метки пишут руками

Функция с **двумя** входными ссылками не может решить, к какой привязать результат:

```rust
fn longest(a: &str, b: &str) -> &str {
    if a.len() > b.len() { a } else { b }
}
```

```text
error[E0106]: missing lifetime specifier
help: this function's return type contains a borrowed value,
      but there is more than one value it could be borrowed from
```

Компилятор честно говорит: «непонятно, от кого из двух аргументов зависит результат». Решение — связать их меткой:

```rust
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() > b.len() { a } else { b }
}
```

`<'a>` — «есть некоторое время жизни `a`»; все три ссылки помечены одной меткой — значит, результат живёт не дольше, чем оба аргумента.

Запомни главное: **ты пишешь метки только когда компилятор не может вывести их сам** — обычно это функции, возвращающие ссылку, и структуры, хранящие ссылки.

## 7. Типичные ошибки

### Рекурсия без `Box`

```text
error[E0072]: recursive type `List` has infinite size
```

### `Rc` в потоке

```text
error[E0277]: `Rc<i32>` cannot be sent between threads safely
```

`Rc` не `Send` — счётчик не атомарный. Нужен `Arc`.

### Два заимствования в `RefCell`

```text
thread 'main' panicked at: already borrowed: BorrowMutError
```

Держи `borrow()` / `borrow_mut()` в одной строке.

### Функция с двумя ссылками без меток

```text
error[E0106]: missing lifetime specifier
```

Свяжи аргументы и результат одной меткой `'a`.

---

## 8. Что ты теперь знаешь

- `Box<T>` — данные в куче, один владелец; нужен для рекурсивных типов.
- `Rc<T>` — несколько владельцев со счётчиком; только в одном потоке.
- `RefCell<T>` — проверка заимствований в рантайме, паника при нарушении.
- `Rc<RefCell<T>>` — общий изменяемый объект.
- Время жизни ссылки — отрезок, пока живы данные; обычно выводится автоматически.
- `'static` — «живёт всю программу»; так помечают литералы.
- Метки `<'a>` пишешь, только когда компилятор не может вывести сам.
