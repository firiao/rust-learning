# Лаба 4. Условия и циклы

**Время:** ~20 минут
**Тема:** `if`, `while`, `loop`, `for`, диапазоны, `break`

## Цель

Пять функций, в каждой нужен **свой** вид цикла — не «какой получится», а подходящий по смыслу.

## Крейт уже создан

Открывай `practice/l04-loops` — копировать ничего не нужно:

- `src/lib.rs` — заготовка: сигнатуры функций с `todo!()` и тесты;
- `Cargo.toml` — пакет `l04-loops`.

`todo!()` — макрос-заглушка: компилируется, но паникует при вызове. Поэтому сейчас тесты **красные**. Это не поломка, а задача: пока `todo!()` на месте, тест падает с `not yet implemented`.

```bash
cargo test -p l04-loops        # сейчас: failures
```

**Почему компилятор предупреждает `unused variable`.** Параметры функций пока не используются — тело заменено на `todo!()`. Это нормально: предупреждения исчезнут сами, как только реализуешь. `cargo test` они не мешают, а `clippy -D warnings` станет чистым **после** реализации.

## Реализуй

Пять функций с `todo!()` в `src/lib.rs`. Какой цикл где уместен — таблица ниже.

```bash
cargo test -p l04-loops
```

Какие циклы где уместны:

| Функция | Цикл | Почему |
|---|---|---|
| `sum_while` | `while` | есть явное условие «пока i ≤ limit» |
| `count_digits` | `while` | делим число, пока не станет 0 |
| `max_digit` | `loop` | условие выхода — внутри, `% 10` и `/ 10` |
| `is_prime` | `for` | перебор диапазона |
| `print_table` | `for` | ровно 5 итераций |

## Эксперимент

Закомментируй `n /= 10;` (или `n = n / 10`) в `count_digits` и запусти тест. Что произойдёт? Почему тест не «упадёт с ошибкой», а **зависнет**?

## Подсказки

<details>
<summary>`sum_while`</summary>

```rust
let mut i = 1;
let mut total = 0;
while i <= limit {
    total += i;
    i += 1;
}
total
```

Обрати внимание на `<=`: `limit` включён.

</details>

<details>
<summary>`count_digits`</summary>

```rust
if n == 0 {
    return 1;
}
let mut n = n;
let mut count = 0;
while n > 0 {
    count += 1;
    n /= 10;
}
count
```

Отдельный случай для 0: иначе цикл не выполнится ни разу и получится 0.

</details>

<details>
<summary>`max_digit`</summary>

```rust
let mut n = n;
let mut best = 0;
loop {
    let digit = (n % 10) as u8;
    if digit > best {
        best = digit;
    }
    n /= 10;
    if n == 0 {
        break;
    }
}
best
```

`loop` уместен, потому что проверка выхода стоит **после** обработки цифры.

</details>

<details>
<summary>`is_prime`</summary>

```rust
if n < 2 {
    return false;
}
for d in 2..n {
    if n.is_multiple_of(d) {
        return false;
    }
}
true
```

`is_multiple_of(d)` — то же, что `n % d == 0`, но `clippy` требует именно такую запись (при `-D warnings` это ошибка, а не совет).

Это наивный вариант — для 97 он проверит 95 делителей. Оптимизация (до `√n`) будет в лабе про итераторы.

</details>

<details>
<summary>`print_table`</summary>

```rust
for i in 1..=5 {
    println!("{n} x {i} = {}", n * i);
}
```

Функция без `->` возвращает `()`, поэтому в конце ничего не нужно.

</details>

<details>
<summary>Почему тест зависает</summary>

Если `n` не меняется, условие `n > 0` остаётся истинным навсегда — бесконечный цикл. Тест не упадёт, а будет висеть, пока его не прервут (`Ctrl+C`).

Это важный навык отладки: **зависание** обычно означает «условие цикла не меняется».

</details>
