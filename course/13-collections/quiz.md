# Тест к лекции 13

Ответы — в конце, под `<details>`.

## Вопросы

**1.** Чем `v[1]` отличается от `v.get(1)`?

a) ничем
b) `[]` паникует при неверном индексе, `get` возвращает `Option`
c) `get` работает только для строк

**2.** Зачем `entry().or_insert(0)`?

a) чтобы удалить ключ
b) чтобы одним поиском получить значение или вставить значение по умолчанию
c) чтобы отсортировать словарь

**3.** Почему порядок обхода `HashMap` нельзя использовать в тестах?

a) он медленный
b) он не определён и может меняться между запусками
c) `HashMap` сортирует по хешу

**4.** Что делает `dedup()` для `[1, 2, 1, 2]`?

a) `[1, 2]`
b) ничего — убирает только **соседние** повторы
c) паникует

**5.** Можно ли использовать `f64` как ключ `HashMap`?

a) да
b) нет: `f64` не реализует `Eq` из-за `NaN`
c) только положительные

**6.** Что вернёт `"привет".len()`?

a) 6
b) 12 — байты
c) 12 — символы

**7.** Что делает `filter_map(|p| p.parse().ok())`?

a) оставляет только ошибки
b) преобразует и отбрасывает неудачные попытки (они стали `None`)
c) сортирует

**8.** Зачем `sort_by` при сортировке `Vec<f64>`?

a) чтобы было быстрее
b) потому что `f64` не реализует `Ord`; сравнивают через `total_cmp`
c) `sort` для `f64` работает

---

## Ответы

<details>
<summary>Показать</summary>

**1 — b.** `[]` — паника при выходе за границы; `get` — `Option<&T>`.

**2 — b.** Один поиск по хеш-таблице вместо `get` + `insert`, без клонирования ключа.

**3 — b.** `HashMap` рандомизирует хеширование; порядок зависит от запуска. Тест, зависящий от
порядка, «мигает».

**4 — b.** Только последовательные дубликаты. Для полной дедупликации — `sort()` и потом `dedup()`.

**5 — b.** `NaN != NaN`, поэтому `Eq` невозможен. Для вещественных ключей берут целые или строки.

**6 — b.** `len()` — байты (кириллица 2 байта на букву). Символы — `chars().count()`.

**7 — b.** `parse()` даёт `Result`; `.ok()` превращает в `Option`; `filter_map` отбрасывает `None`.

**8 — b.** У `f64` нет полного порядка (`Ord`) из-за `NaN`. `total_cmp` даёт корректное сравнение.

</details>
