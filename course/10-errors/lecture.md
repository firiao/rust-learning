# Лекция 10. Ошибки и `Result`

**Время:** ~30 минут

**Нужно знать заранее:** `enum`, `Option`, `match`, `if let`, методы, `impl`.

**Новые слова в этой лекции:**
- **`Result<T, E>`** — перечисление «успех с результатом `T` или ошибка `E`»;
- **`Ok`** — вариант «всё получилось»;
- **`Err`** — вариант «ошибка»;
- **паника (`panic!`)** — аварийная остановка программы;
- **`?`** — оператор «если ошибка — верни её наверх, иначе разверни значение»;
- **`Display`** — «умение печататься для пользователя» (запись `{}`);
- **`Error`** — стандартное «свойство ошибки», которое даёт совместимость с остальной экосистемой.

---

## 1. От `Option` к `Result`

`Option<T>` отвечает на вопрос «есть значение или нет». Но часто важно **почему** значения нет: не число, а текст не парсится; файла нет; делить на ноль нельзя.

`None` не умеет рассказать причину — он не несёт данных. Нужен второй вариант, где ошибка **несёт информацию**.

```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

Разберём:

- `Result` — имя типа (от англ. *result*, «результат»);
- `<T, E>` — два параметра типа: `T` — что вернётся при успехе, `E` — что при ошибке;
- `Ok(T)` — вариант «успех», внутри результат;
- `Err(E)` — вариант «ошибка», внутри причина.

Это встроенное перечисление стандартной библиотеки, ровно как `Option`. Никакой магии: обычный `enum` с двумя вариантами.

---

## 2. Первый пример

```rust
fn divide(a: f64, b: f64) -> Result<f64, String> {
    if b == 0.0 {
        return Err(String::from("делить на ноль нельзя"));
    }
    Ok(a / b)
}

fn main() {
    match divide(10.0, 2.0) {
        Ok(value) => println!("получилось {value}"),
        Err(message) => println!("ошибка: {message}"),
    }

    match divide(1.0, 0.0) {
        Ok(value) => println!("получилось {value}"),
        Err(message) => println!("ошибка: {message}"),
    }
}
```

```text
получилось 5
ошибка: делить на ноль нельзя
```

Разберём сигнатуру: `fn divide(a: f64, b: f64) -> Result<f64, String>` — «принимает два дробных числа, возвращает либо `f64`, либо `String` с описанием ошибки».

Важно: **в сигнатуре видно, что функция может вернуть ошибку**. Это главное отличие от исключений в Python: там ты не узнаешь из описания функции, бросит ли она исключение. В Rust это написано в типе.

### Почему не `String`

`Err(String)` — простой вариант для учёбы, но в реальном коде так не делают: вызывающий не может отличить «делить на ноль» от «нет файла», не сравнивая текст сообщения. Правильнее — свой `enum` ошибок. Об этом в разделе 6.

## 3. Оператор `?`

Обрабатывать `match`-ем **каждый** вызов утомительно. Представь функцию из пяти шагов, каждый может упасть — пять `match`-ей подряд.

Для этого есть оператор **`?`**:

```rust
fn parse_and_double(text: &str) -> Result<i32, String> {
    let number: i32 = text
        .trim()
        .parse()
        .map_err(|_| format!("не число: {text:?}"))?;

    Ok(number * 2)
}
```

Разберём медленно:

- `text.trim()` — убрать пробелы по краям (метод строки);
- `.parse()` — превратить текст в число; возвращает `Result<i32, ParseIntError>`;
- `.map_err(|_| ...)` — если ошибка, **заменить** её своей строкой. Замыкание `|_| ...` — «принять ошибку и вернуть вот это» (замыкания подробно в лекции 15);
- `?` в конце — **если получился `Err`, вернуть его из функции немедленно; если `Ok` — развернуть значение в переменную `number`**.

То есть `?` делает две вещи: при ошибке — ранний выход, при успехе — достаёт значение.

Без `?` тот же код был бы:

```rust
let number: i32 = match text.trim().parse() {
    Ok(n) => n,
    Err(_) => return Err(format!("не число: {text:?}")),
};
```

`?` — это ровно этот `match`, но в один символ. Читается как «выполни, а если ошибка — выйди».

### Условие: функция должна возвращать `Result`

`?` не работает в функции, которая ничего не возвращает:

```rust
fn main() {
    let x: i32 = "5".parse()?;   // ошибка
}
```

```text
error[E0277]: the `?` operator can only be used in a function that returns
              `Result` or `Option` (or another type that implements `FromResidual`)
```

(текст сокращён; последняя часть про `FromResidual` — уже за пределами курса, тебе она пока не нужна)

Смысл: `?` при ошибке должен что-то **вернуть**, значит функция обязана возвращать `Result` (или `Option`). В `main` можно, если объявить `main` возвращающей `Result` — это будет ниже.

## 4. `panic!` — аварийная остановка

`panic!` — макрос, который **немедленно** останавливает программу:

```rust
fn main() {
    let numbers = [1, 2, 3];
    println!("{}", numbers[10]);   // выход за границы — паника
}
```

```text
thread 'main' panicked at main.rs:3:20:
index out of bounds: the len is 3 but the index is 10
```

Паника — это «программа сломалась». Её нельзя «обработать» так же просто, как `Result`.

Когда `panic!` уместен:

- **баг в коде**, который «не может случиться»: нарушен внутренний инвариант;
- учебный код и тесты;
- ситуация, когда продолжать бессмысленно.

Когда **не** уместен:

- ошибка ввода пользователя;
- файла нет;
- число не парсится.

Это ожидаемые ситуации: их обрабатывают через `Result`, а не паникой.

| | `panic!` | `Result` |
|---|---|---|
| Кто решает, что делать | никто, программа падает | вызывающий |
| Когда | баг, нарушенный инвариант | ожидаемая проблема |
| В библиотеке | почти никогда | почти всегда |

### `unwrap` и `expect`

`unwrap()` мы видели у `Option`; у `Result` он тоже есть:

```rust
let value: i32 = "42".parse().unwrap();      // 42
let bad: i32 = "abc".parse().unwrap();       // паника
```

```text
thread 'main' panicked at:
called `Result::unwrap()` on an `Err` value: ParseIntError { kind: InvalidDigit }
```

`expect("сообщение")` — то же самое, но добавляет твой текст:

```rust
let value: i32 = "abc".parse().expect("возраст должен быть числом");
```

```text
thread 'main' panicked at:
возраст должен быть числом: ParseIntError { kind: InvalidDigit }
```

`expect` лучше `unwrap`: при падении сразу видно, **что** искали.

## 5. `main`, которая возвращает `Result`

У `main` тоже можно указать тип возврата:

```rust
use std::fs;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let text = fs::read_to_string("заметки.txt")?;
    println!("размер файла: {} байт", text.len());
    Ok(())
}
```

Разберём:

- `-> Result<(), Box<dyn std::error::Error>>` — «возвращает либо ничего при успехе (`()`), либо любую ошибку»;
- `Box<dyn Error>` — «коробка с любой ошибкой». `Box` — умный указатель на данные в куче, `dyn Error` — «какая-то ошибка». Полностью это будет в лекциях 17 и 11; сейчас важно: это способ сказать «ошибка любого вида»;
- `fs::read_to_string(path)` — прочитать файл целиком в `String`;
- `Ok(())` в конце — «всё хорошо, ничего не возвращаю».

Если файл не найдётся, `?` вернёт ошибку из `main`, Rust напечатает её и завершит программу с кодом 1.

## 6. Своя ошибка

Правильный способ для библиотеки — свой `enum`:

```rust
use std::fmt;

#[derive(Debug, PartialEq)]
enum ParseError {
    Empty,
    NotANumber(String),
    OutOfRange { value: i64, min: i64, max: i64 },
}
```

Три варианта — три разные причины. Теперь вызывающий может **различить** их:

```rust
match parse_age(input) {
    Ok(age) => println!("возраст {age}"),
    Err(ParseError::Empty) => println!("введи хоть что-нибудь"),
    Err(e) => println!("{e}"),
}
```

Чтобы ошибку можно было печатать через `{}`, нужно реализовать `Display`:

```rust
impl fmt::Display for ParseError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            ParseError::Empty => write!(f, "пустая строка"),
            ParseError::NotANumber(s) => write!(f, "не число: {s:?}"),
            ParseError::OutOfRange { value, min, max } => {
                write!(f, "{value} вне диапазона {min}..={max}")
            }
        }
    }
}

impl std::error::Error for ParseError {}
```

Что здесь новое:

- `impl fmt::Display for ParseError` — реализация **трейта** `Display` для нашего типа. Трейт — «свойство, которое тип умеет»; `Display` — «умеет печататься для пользователя». Подробно трейты в лекции 11; сейчас достаточно знать, что так говорят компилятору, как печатать наш тип через `{}`;
- `fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result` — обязательный метод этого трейта. `f` — «куда писать», через `write!(f, ...)` пишем текст;
- `write!` — как `println!`, но не в консоль, а в переданное место;
- `{s:?}` — отладочный вывод строки (в кавычках). Мы видели `{:?}` в лекции 7;
- `impl std::error::Error for ParseError {}` — пустая реализация. Она говорит: «это настоящая ошибка», чтобы тип работал с `?`, `Box<dyn Error>` и экосистемой.

Теперь функция:

```rust
fn parse_age(text: &str) -> Result<u8, ParseError> {
    let trimmed = text.trim();

    if trimmed.is_empty() {
        return Err(ParseError::Empty);
    }

    let value: i64 = match trimmed.parse() {
        Ok(v) => v,
        Err(_) => return Err(ParseError::NotANumber(trimmed.to_string())),
    };

    if !(0..=150).contains(&value) {
        return Err(ParseError::OutOfRange { value, min: 0, max: 150 });
    }

    Ok(value as u8)
}
```

По шагам:

1. `trimmed.is_empty()` — пустая строка → `Empty`;
2. `trimmed.parse()` — попытка превратить в `i64`. При ошибке — `NotANumber`;
3. `(0..=150).contains(&value)` — проверка диапазона; метод `contains` у диапазона проверяет, входит ли значение. `&value` — потому что `contains` принимает ссылку;
4. `Ok(value as u8)` — успех, приведение `i64` к `u8`.

## 7. Типичные ошибки

### `?` вне функции с `Result`

```text
error[E0277]: the `?` operator can only be used in a function that returns
              `Result` or `Option`
```

Смени тип возврата функции или обработай ошибку через `match`.

### Проигнорировали `Result`

```rust
fn main() {
    "abc".parse::<i32>();
}
```

```text
warning: unused `Result` that must be used
```

Компилятор **предупреждает**: результат-ошибку проигнорировали. Это почти всегда баг. Обработка: `let _ = ...;` если правда не важно, лучше — `?` или `match`.

### `unwrap` на `Err`

```text
thread 'main' panicked at: called `Result::unwrap()` on an `Err` value
```

`unwrap` не «обрабатывает» ошибку — он паникует.

---

## 8. Что ты теперь знаешь

- `Result<T, E>` — перечисление `Ok(T)` / `Err(E)`; встроено в стандартную библиотеку.
- В сигнатуре функции видно, что она может вернуть ошибку.
- `?` — ранний выход при ошибке и разворачивание при успехе; работает только в функциях, возвращающих `Result`/`Option`.
- `panic!` — для багов и нарушенных инвариантов, не для ожидаемых проблем.
- `expect` лучше `unwrap`: сообщение при панике будет информативнее.
- Своя ошибка — `enum` + `impl Display` + `impl std::error::Error`.
- `main` может возвращать `Result`.
