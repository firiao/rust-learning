# Тест к лекции 10

Ответы — в конце, под `<details>`.

## Вопросы

**1.** Чем `Result<T, E>` отличается от `Option<T>`?

a) ничем
b) у `Err` есть причина (`E`), у `None` причины нет
c) `Result` только для чисел

**2.** Когда уместен `panic!`?

a) файл не найден
b) нарушен инвариант, который программист считает невозможным
c) пользователь ввёл неверные данные

**3.** Что делает `?` при `Err(e)`?

a) печатает ошибку и продолжает
b) досрочно возвращает `Err(e)` из функции
c) паникует

**4.** Почему `?` не работает в функции, возвращающей `()`?

a) `?` должен что-то вернуть, а возвращать нечего
b) `?` работает только в `main`
c) работает и так

**5.** Чем `expect("текст")` лучше `unwrap()`?

a) не паникует
b) при панике печатает твой текст — понятно, что искали
c) работает быстрее

**6.** Зачем `impl Display for MyError`?

a) чтобы ошибку можно было печатать через `{}`
b) чтобы она стала потокобезопасной
c) это обязательно для `match`

**7.** Зачем `impl std::error::Error for MyError {}`?

a) без него `Display` не работает
b) чтобы тип считался настоящей ошибкой: работал с `?`, `Box<dyn Error>` и экосистемой
c) это ускоряет

**8.** Что сделает `main() -> Result<(), Box<dyn Error>>` при ошибке?

a) проигнорирует
b) напечатает ошибку и завершит программу с кодом 1
c) запаникует

**9.** Почему `Err(String)` — плохой выбор для библиотеки?

a) строки медленные
b) вызывающий не отличит одну ошибку от другой, не сравнивая текст
c) `String` нельзя вернуть

---

## Ответы

<details>
<summary>Показать</summary>

**1 — b.** `Option` — «есть/нет», `Result` — «успех/ошибка с причиной».

**2 — b.** Паника — аварийная остановка для «этого не должно было случиться». Ожидаемые проблемы
(ввод, файлы) — через `Result`.

**3 — b.** Немедленный выход из функции с той же ошибкой. Разворачивание `Ok(v)` — если ошибки нет.

**4 — a.** `?` при ошибке возвращает значение, а `()` возвращать нечего. Нужно сменить тип возврата.

**5 — b.** Оба паникуют, но `expect` добавляет понятное сообщение.

**6 — a.** `{}` работает через трейт `Display`.

**7 — b.** `Error` — общий протокол ошибок (лекция 11 объяснит трейты).

**8 — b.** Rust напечатает `Error: ...` и выйдет с кодом 1.

**9 — b.** Тип ошибки стёрт: вызывающий не сделает «если файла нет — создай, если формат плохой — сообщи».

</details>
