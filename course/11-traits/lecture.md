# Лекция 11. Трейты

**Время:** ~30 минут

**Нужно знать заранее:** `struct`, `impl`, методы, `enum`, `match`, `Display` из лекции 10.

**Новые слова в этой лекции:**
- **трейт** — набор требований к поведению: «тип умеет вот это»;
- **реализация трейта** — `impl Трейт for Тип` — «этот тип умеет то, что требует трейт»;
- **метод по умолчанию** — метод в трейте с готовым телом; реализовывать не обязательно;
- **трейт-объект** — значение вида `dyn Трейт` — «какой-то тип, умеющий этот трейт, но какой именно — неизвестно до запуска»;
- **`dyn`** — слово, которое это обозначает;
- **`Box<dyn Трейт>`** — трейт-объект, которым владеют (об `Box` подробно в лекции 17, здесь нужно только «упаковка для значения неизвестного размера»).

---

## 1. Задача

В лекции 10 мы уже писали такое:

```rust
impl fmt::Display for ParseError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result { ... }
}
```

Это была «реализация трейта `Display`». Тогда мы проскочили — теперь разберём, что это значит.

Задача: у разных типов бывает **одинаковое поведение**. И `Circle`, и `Rectangle`, и `Triangle` умеют считать площадь. Как сказать «все эти типы умеют считать площадь», не копируя код три раза и не заводя общего родителя?

В Java для этого есть интерфейс, в Python — «утиная типизация» (если есть метод `.area()` — значит подойдёт). В Rust — **трейт**.

---

## 2. Объявление трейта

```rust
trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> &'static str;
}
```

Разберём:

- `trait` — слово, объявляющее трейт;
- `Shape` — имя трейта (стиль — с большой буквы, как у типов);
- внутри — **требования**: методы **без тела**. Здесь сказано: «тот, кто хочет быть `Shape`, обязан уметь `area` и `name`».

Трейт — это **контракт**, а не код. Он ничего не вычисляет, он требует.

`&'static str` — «ссылка на текст, живущий всю программу». Так получается, когда метод возвращает строковый литерал `"круг"`. Метка `'static` здесь означает «этот текст не будет освобождён никогда»; литералы такие всегда.

---

## 3. Реализация трейта для типа

Теперь скажем, что наши структуры этому контракту соответствуют.

```rust
struct Circle {
    radius: f64,
}

struct Square {
    side: f64,
}

impl Shape for Circle {
    fn area(&self) -> f64 {
        std::f64::consts::PI * self.radius * self.radius
    }

    fn name(&self) -> &'static str {
        "круг"
    }
}

impl Shape for Square {
    fn area(&self) -> f64 {
        self.side * self.side
    }

    fn name(&self) -> &'static str {
        "квадрат"
    }
}
```

Разберём запись `impl Shape for Circle`:

- `impl` — «реализация» (та же буква, что в лекции 7);
- `Shape` — **какой** трейт реализуем;
- `for` — «для»;
- `Circle` — **какой** тип.

Целиком: «`Circle` реализует `Shape`». Внутри — тела методов, которые требует трейт.

Важно: **`Circle` не становится подтипом `Shape`**. Наследования в Rust нет. Есть только утверждение «`Circle` умеет быть `Shape`». Разница практическая: трейт можно реализовать для типа, который ты не писал (например, для `Vec`, если трейт твой).

---

## 4. Методы по умолчанию

В трейте можно дать готовое тело. Тогда реализующий тип может его **не переопределять**:

```rust
trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> &'static str;

    // тело уже есть — реализовывать не обязательно
    fn describe(&self) -> String {
        format!("{} площадью {:.2}", self.name(), self.area())
    }
}
```

Теперь `Circle` и `Square` получают `describe()` бесплатно, потому что у них есть `area` и `name`.

```rust
let c = Circle { radius: 1.0 };
println!("{}", c.describe());   // круг площадью 3.14
```

`{:.2}` — форматирование: «два знака после запятой».

Если поведение по умолчанию не подходит, метод можно переопределить в `impl` — тогда используется своя версия.

## 5. Использование: «принимаю что угодно, что умеет `Shape`»

Вот главное, зачем трейты нужны.

### Через `dyn`

```rust
fn total_area(shapes: &[&dyn Shape]) -> f64 {
    shapes.iter().map(|s| s.area()).sum()
}

fn main() {
    let c = Circle { radius: 1.0 };
    let s = Square { side: 2.0 };

    let shapes: Vec<&dyn Shape> = vec![&c, &s];
    println!("{}", total_area(&shapes));
}
```

Разберём по частям:

- `&dyn Shape` — «ссылка на что-то, что умеет `Shape`». Слово **`dyn`** означает «тип будет известен только во время выполнения»;
- `&[&dyn Shape]` — «срез ссылок на трейт-объекты», то есть список разных фигур;
- `vec![&c, &s]` — макрос создания `Vec` (список); подробно в лекции 13;
- `shapes.iter().map(|s| s.area()).sum()` — «пройти по каждому, взять площадь, сложить»; подробно в лекции 14.

Ключевой момент: **в одном списке лежат разные типы** — `Circle` и `Square`. Это возможно только потому, что тип «спрятан» за `dyn Shape`.

### Почему нужен `dyn`, а не просто `Shape`

`Shape` — это не тип, а контракт. Сколько байт занимает «что-то, умеющее Shape»? Неизвестно: `Circle` — это 8 байт, `Square` — тоже 8, но завтра появится `Triangle` с тремя полями. Компилятор не может выделить память под неизвестный размер.

`dyn Shape` — это **трейт-объект**: внутри лежит указатель на данные и таблица методов. Размер фиксирован (два указателя), а конкретный тип определяется при вызове.

### Сравнение с `enum`

В лекции 9 мы делали `enum Shape { Circle, Rectangle, Empty }` — и это тоже «одно из». Когда что выбирать?

| | `enum` | `trait` + `dyn` |
|---|---|---|
| Набор вариантов | закрытый: известен заранее | открытый: любой тип может присоединиться |
| Добавить новый вариант | правишь `enum` и все `match` | просто реализуешь трейт |
| Размер значения | известен компилятору | только за `Box`/`&` |
| Скорость | быстрее (прямой вызов) | чуть медленнее (через таблицу) |

Правило: **варианты известны и их немного → `enum`. Набор открыт или типы приходят извне → трейт.**

## 6. `derive` — это автоматическая реализация трейтов

Теперь `#[derive(Debug, Clone, PartialEq)]` из лекции 7 наконец объясняется полностью.

`derive` просит компилятор **написать за тебя `impl`** для стандартных трейтов:

```rust
#[derive(Debug, Clone, PartialEq)]
struct Product {
    name: String,
}
```

эквивалентно тому, что кто-то написал:

```rust
impl std::fmt::Debug for Product { ... }
impl Clone for Product { ... }
impl PartialEq for Product { ... }
```

Только делает это генератор кода — **процедурный макрос** (тот самый «отдельно скомпилированный и запускаемый при сборке» из нашего разговора про макросы).

Поэтому:

- `Debug` можно вывести, потому что правило простое: «напечатай имя типа и все поля»;
- `Display` **нельзя** вывести: компилятор не знает, как ты хочешь видеть товар в отчёте. Его пишут руками — как мы делали для `ParseError` в лекции 10.

Атрибут `#[derive(...)]` — общий синтаксис: `#[...]` называется **атрибутом** и даёт компилятору дополнительную информацию о том, что идёт дальше. Раньше мы видели `#[cfg(test)]` и `#[test]` — это тоже атрибуты.

## 7. Стандартные трейты, которые нужно знать

| Трейт | Что требует | Откуда взять |
|---|---|---|
| `Debug` | печать для отладки `{:?}` | `#[derive(Debug)]` |
| `Display` | печать для пользователя `{}` | писать руками |
| `Clone` | метод `.clone()` | `#[derive(Clone)]` |
| `Copy` | копирование вместо перемещения (лекция 5) | `#[derive(Copy)]`, только если все поля `Copy` |
| `PartialEq` | сравнение `==` | `#[derive(PartialEq)]` |
| `PartialOrd` | сравнение `<`, `>` | `#[derive(PartialOrd)]` |
| `Default` | значение по умолчанию | `#[derive(Default)]` или руками |
| `Error` | «это ошибка» | пустой `impl std::error::Error for ... {}` (лекция 10) |

`Copy` и `Clone` — связаны: `Copy` требует, чтобы тип можно было скопировать побайтово, `Clone` — просто «умеет делать копию». Поэтому `Copy` требует `Clone`.

## 8. Типичные ошибки

### Тип не реализует трейт

```rust
fn print_area(shape: &dyn Shape) {
    println!("{}", shape.area());
}

struct Line { length: f64 }

fn main() {
    let l = Line { length: 2.0 };
    print_area(&l);
}
```

```text
error[E0277]: the trait bound `Line: Shape` is not satisfied
```

`trait bound ... is not satisfied` — «требование не выполнено». Нужно `impl Shape for Line`.

### Реализовал не все методы

```rust
impl Shape for Line {
    fn area(&self) -> f64 { 0.0 }
}
```

```text
error[E0046]: not all trait items implemented, missing: `name`
```

`missing: name` — забыл метод, который требует трейт.

### `dyn` без ссылки

```rust
fn takes(shape: dyn Shape) { }
```

```text
error[E0277]: the size for values of type `(dyn Shape + 'static)` cannot be known at compilation time
```

Размер `dyn Shape` неизвестен — компилятор дописывает `+ 'static` (время жизни по умолчанию, для нас сейчас неважно). Нужно `&dyn Shape` (одолжить) или `Box<dyn Shape>` (упаковать в кучу).

---

## 9. Что ты теперь знаешь

- Трейт — контракт «тип умеет вот это»; в нём методы без тела (или с телом по умолчанию).
- `impl Трейт for Тип` — реализация контракта для конкретного типа.
- Наследования нет: тип не «является» другим, он «умеет».
- `dyn Трейт` — трейт-объект: конкретный тип неизвестен до запуска, поэтому нужен `&` или `Box`.
- `enum` — закрытый набор вариантов, трейт — открытый.
- `#[derive(...)]` — автогенерация `impl` для стандартных трейтов; `Display` так не выводится.
