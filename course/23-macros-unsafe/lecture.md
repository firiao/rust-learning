# Лекция 23. Макросы и unsafe

**Время:** ~30 минут

**Нужно знать заранее:** всё про функции, трейты, `unsafe` не встречалось.

**Новые слова в этой лекции:**
- **`macro_rules!`** — способ писать свои макросы «по шаблону»;
- **правило макроса** — пара «что ищем» `=>` «что подставляем»;
- **`$имя:вид`** — захват части кода в макросе;
- **`unsafe`** — блок, в котором компилятор отключает часть проверок;
- **FFI** — вызов кода на другом языке (обычно C);
- **soundness** — «безопасность»: `unsafe`-код не должен ломать гарантии Rust.

---

## 1. `macro_rules!` — макрос по шаблону

Мы уже знаем, что макрос разворачивается во время компиляции в обычный код (лекция 1). Теперь — как написать свой.

```rust
macro_rules! square {
    ($x:expr) => {
        $x * $x
    };
}

fn main() {
    println!("{}", square!(5));        // 25
    println!("{}", square!(2 + 3));    // 25
}
```

Разберём:

- `macro_rules!` — объявление макроса;
- `square` — имя. Макросы вызываются с `!`;
- `($x:expr) => { ... }` — **правило**: «если в скобках пришло выражение, назови его `$x`»;
- `$x:expr` — `$` означает «переменная макроса», `:expr` — «вид: выражение»;
- `$x * $x` — подстановка.

Важно: макрос работает **с кодом**, а не со значениями. `square!(2 + 3)` подставляет `2 + 3 * 2 + 3`? Нет — `:expr` сохраняет группировку, поэтому получится `(2 + 3) * (2 + 3)`. Это одно из преимуществ `:expr` перед текстовой подстановкой из C.

### Виды захвата

| Вид | Что принимает |
|---|---|
| `$x:expr` | выражение |
| `$x:ident` | идентификатор (имя) |
| `$x:ty` | тип |
| `$x:literal` | литерал (число, строка) |
| `$x:block` | блок `{ ... }` |
| `$x:pat` | шаблон для `match` |

### Несколько правил

```rust
macro_rules! describe {
    (число $x:expr) => {
        format!("число {}", $x)
    };
    (строка $x:expr) => {
        format!("строка {:?}", $x)
    };
}

fn main() {
    println!("{}", describe!(число 42));
    println!("{}", describe!(строка "привет"));
}
```

Правила проверяются сверху вниз, срабатывает первое подходящее — как `match` (лекция 8).

### Повторение

```rust
macro_rules! vec_of_strings {
    ($($x:expr),*) => {
        vec![$(String::from($x)),*]
    };
}

fn main() {
    let v = vec_of_strings!("а", "б", "в");
    println!("{:?}", v);       // ["а", "б", "в"]
}
```

`$( ... ),*` — «повторить для каждого элемента, разделённого запятой». Это та самая механика, на которой держатся `vec!` и `println!`.

### Когда писать макросы

Почти никогда. Макрос — это код, который генерирует код; его тяжело читать, отлаживать и документировать. Начинать надо с функций и обобщений.

Макрос уместен, когда нужна **переменная структура вызова**: как у `println!` (любое число аргументов) или `vec!` (любое число элементов).

## 2. `unsafe` — выключить часть проверок

Rust гарантирует безопасность памяти. Но есть операции, которые проверить нельзя: вызов кода на C, работа с «сырыми» указателями, ручная реализация структур данных.

Для них есть `unsafe`-блок:

```rust
fn main() {
    let x = 5;

    let raw = &x as *const i32;      // «сырой» указатель

    unsafe {
        println!("{}", *raw);        // разыменование требует unsafe
    }
}
```

Разберём:

- `&x as *const i32` — превратить ссылку в «сырой» указатель. `*const T` — указатель, который компилятор не проверяет;
- `unsafe { ... }` — блок, в котором разрешено то, что обычно запрещено;
- `*raw` — разыменование сырого указателя. Это опасная операция: если указатель «протух», будет неопределённое поведение.

### Что разрешает `unsafe`

| Возможность | Зачем |
|---|---|
| разыменовать сырой указатель | структуры данных, FFI |
| вызвать `unsafe fn` | C-функции, низкоуровневые API |
| обратиться к `static mut` | глобальное изменяемое состояние |
| реализовать `unsafe trait` | `Send`/`Sync` вручную (лекция 18) |
| работать с объединениями (`union`) | представление данных как в C |

Что `unsafe` **не** разрешает: нарушать правила владения и заимствования. Компилятор всё равно проверит их снаружи. `unsafe` — это «я ручаюсь за эти несколько строк», а не «выключи Rust».

### Пример: вызов C-функции

```rust
unsafe extern "C" {
    fn abs(input: i32) -> i32;
}

fn main() {
    unsafe {
        println!("{}", abs(-5));     // 5
    }
}
```

`unsafe extern "C" { ... }` — объявление функций, написанных на C (или совместимых с C ABI). Их вызов всегда `unsafe`: Rust не может проверить, что там внутри.

Почему `unsafe` стоит и перед `extern`: начиная с edition 2024 сам блок объявления внешних функций тоже помечается `unsafe`. Раньше было можно без него — в старом коде ты увидишь просто `extern "C" {`; если переносишь такой код в edition 2024, добавь `unsafe`.

### Правило поведения с `unsafe`

1. **Не пиши** `unsafe`, пока не умеешь без него.
2. **Читать** чужой `unsafe` нужно уметь — но обычно достаточно понять, что он делает.
3. Если в крейте есть `unsafe`, смотри, не нарушает ли он правила: `unsafe`-код обязан сохранять все гарантии Rust — это и называется **soundness**.
4. `#![forbid(unsafe_code)]` в начале файла — запрет `unsafe` во всём крейте. Многие библиотеки так и делают.

## 3. Итог: чего не делать

| Не надо | Почему |
|---|---|
| писать макрос вместо функции | макросы тяжело читать и отлаживать |
| использовать `unsafe` «для скорости» | компилятор и так оптимизирует; выигрыш обычно нулевой |
| `unsafe` без комментария | непонятно, почему это безопасно |
| реализовывать `Send`/`Sync` руками | почти всегда ошибка |

---

## 4. Что ты теперь знаешь

- `macro_rules!` — макрос по шаблону: `($x:expr) => { ... }`.
- `$x:expr` — захват выражения; `$(...),*` — повторение.
- Макрос оправдан, когда нужна переменная форма вызова.
- `unsafe` разрешает сырые указатели, FFI, `static mut`.
- `unsafe` не отключает проверки владения.
- `unsafe`-код обязан сохранять гарантии (soundness).
