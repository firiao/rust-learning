# Лекция 19. Cargo глубже

**Время:** ~25 минут

**Нужно знать заранее:** лекцию 1 (что такое Cargo) и базовый синтаксис `Cargo.toml`.

**Новые слова в этой лекции:**
- **зависимость** — чужая библиотека, которую использует твой проект;
- **semver** — версии вида `1.2.3`; правила совместимости;
- **`Cargo.lock`** — файл с точными версиями, зафиксированными при сборке;
- **feature** — необязательная часть библиотеки, включаемая по выбору;
- **профиль сборки** — набор настроек (`dev`, `release`);
- **`cargo tree`** — посмотреть дерево зависимостей;
- **`dbg!`** — макрос отладочной печати.

---

## 1. `Cargo.toml` целиком

```toml
[package]
name = "my-app"          # имя пакета
version = "0.1.0"        # своя версия
edition = "2024"         # правила языка

[dependencies]
serde = { version = "1", features = ["derive"] }
serde_json = "1"

[dev-dependencies]
tempfile = "3"           # только для тестов

[profile.release]
opt-level = 3
lto = true
```

Разберём:

- `[dependencies]` — библиотеки, нужные программе;
- `[dev-dependencies]` — нужны **только тестам**; в релизный бинарник не попадают;
- `[profile.release]` — настройки оптимизированной сборки;
- `{ version = "1", features = ["derive"] }` — зависимость с включёнными **feature** (см. ниже).

Добавлять зависимости руками не обязательно:

```bash
cargo add serde --features derive
cargo add serde_json
cargo add --dev tempfile
```

`cargo add` сам допишет нужные строки.

## 2. Версии и `Cargo.lock`

Версия `1.2.3` — это `major.minor.patch` (semver).

| Запись | Что разрешает |
|---|---|
| `"1.2.3"` | `>=1.2.3, <2.0.0` |
| `"1.2"` | `>=1.2.0, <2.0.0` |
| `"1"` | `>=1.0.0, <2.0.0` |
| `"=1.2.3"` | строго `1.2.3` |
| `"*"` | любую (не делай так) |

Cargo считает, что `major` меняется только при несовместимых изменениях. Это обещание автора библиотеки, а не магия компилятора.

**`Cargo.lock`** фиксирует **точные** версии всех зависимостей, включая транзитивные. Он создаётся при первой сборке:

```bash
cargo build      # создаст/обновит Cargo.lock
```

Правило: для приложений `Cargo.lock` **коммитят** (чтобы у всех были одинаковые версии), для библиотек — тоже (с 2023 года это рекомендация Cargo).

## 3. Feature — необязательные части библиотеки

Библиотека может содержать больше, чем тебе нужно. Чтобы не тащить лишнее в бинарник, части включают флагами.

Пример: `serde` без feature умеет только объявлять трейты. Чтобы работал `#[derive(Serialize)]`, нужна feature `derive`:

```toml
[dependencies]
serde = { version = "1", features = ["derive"] }
```

Посмотреть, какие features есть у крейта:

```bash
cargo info serde
```

Свои features объявляют так:

```toml
[features]
default = ["json"]
json = ["dep:serde_json"]
```

`default` — что включено по умолчанию. `dep:serde_json` — «включить эту зависимость».

## 4. Workspace — несколько пакетов в одном проекте

Если проект состоит из нескольких крейтов, их связывают в **workspace**:

```toml
[workspace]
resolver = "3"
members = [
    "app",        # программа
    "core",       # библиотека с логикой
]
```

Что даёт:

- общая папка `target/` — сборка не дублируется;
- общий `Cargo.lock` — одинаковые версии;
- `cargo test --workspace` — прогнать всё;
- `cargo test -p core` — один пакет.

Внутри workspace пакет ссылается на соседа так:

```toml
[dependencies]
core = { path = "../core" }
```

В нашем учебном курсе так и сделано: корневой `Cargo.toml` — workspace, а `practice/*` — его члены.

## 5. Профили сборки

| Профиль | Когда | Оптимизации | Проверки |
|---|---|---|---|
| `dev` (по умолчанию) | `cargo build`, `cargo run` | нет | есть (переполнение → паника) |
| `release` | `cargo build --release` | есть | нет |

Можно настроить:

```toml
[profile.dev]
opt-level = 1            # чуть оптимизировать даже в dev

[profile.release]
lto = true               # межкрейтовая оптимизация (медленнее сборка, быстрее код)
codegen-units = 1        # максимум оптимизации
```

Это уже тонкая настройка; понадобится, когда программа станет медленной.

## 6. Полезные команды

```bash
cargo tree                # дерево зависимостей
cargo tree -d             # где дублируются версии
cargo tree -i serde       # кто зависит от serde
cargo doc --open          # собрать и открыть документацию своего проекта
cargo doc --no-deps      # только своя документация, без зависимостей
cargo update              # обновить версии в пределах semver
cargo clean               # удалить target/
cargo metadata            # всё о проекте в JSON (для инструментов)
```

`cargo tree` — первое, что стоит запускать, когда сборка стала медленной: видно, кто тянет лишнее.

## 7. `dbg!` — отладочная печать

Макрос, который печатает **и выражение, и его значение**, и возвращает значение обратно:

```rust
fn main() {
    let x = 5;
    let y = dbg!(x * 2);
    println!("{y}");
}
```

```text
[src/main.rs:3:13] x * 2 = 10
10
```

Пишет в `stderr` (то есть не мешает данным в `stdout`) и показывает файл и строку. В отличие от `println!`, его не нужно потом убирать аккуратно — выражение остаётся рабочим.

## 8. Что делать, когда сборка падает

Частые причины и что смотреть:

| Симптом | Что делать |
|---|---|
| `failed to select a version` | конфликт версий; `cargo tree -d` |
| `linker not found` | нет системного компилятора (`gcc`/`cc`) |
| долгая сборка | `cargo build --timings` |
| непонятная ошибка в чужом крейте | `cargo build -v` покажет команды |
| «не хватает системной библиотеки» | у крейта есть требования к ОС; смотри README |

## 9. Что ты теперь знаешь

- `[dependencies]` — рабочие зависимости, `[dev-dependencies]` — только для тестов.
- Версия `"1.2.3"` значит `>=1.2.3, <2.0.0`; `Cargo.lock` фиксирует точные версии.
- Feature включает необязательные части библиотеки.
- Workspace объединяет несколько пакетов: общий `target/` и `Cargo.lock`.
- Профили `dev`/`release` отличаются оптимизациями и проверками.
- `cargo tree`, `cargo doc`, `dbg!` — ежедневные инструменты.
