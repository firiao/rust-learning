# Курс Rust с нуля до junior (ML-трек)

Курс для человека, который **никогда не видел Rust**. Построен под ML-инженера: сначала язык, но прикладные и ML-задачи идут параллельно, а не «когда-нибудь потом».

---

## Правила курса

> **Ни одно слово и ни одна конструкция не используются раньше, чем объяснены.**

Из этого следует:

1. **В начале лекции — список новых слов** с определением в одну строку.
2. **Каждый блок кода разобран построчно** — что означает каждая часть, а не «вот пример».
3. **Никаких «так надо».** Если что-то выглядит странно — объясняется причина.
4. **Забегания вперёд объясняются на месте.** Бывает, что конструкцию нужно упомянуть раньше полного разбора. Тогда прямо в тексте сказано, что она делает, а полный разбор даётся позже. Все такие места выписаны в [FORWARD-REFERENCES.md](FORWARD-REFERENCES.md) — можешь проверить, что ничего не спрятано.
5. **Есть словарь** — [GLOSSARY.md](GLOSSARY.md). Растёт вместе с курсом.

Если встретил необъяснённое слово — это ошибка курса, а не твоя. Пиши.

## Как проходить лабу

Крейты для лаб **уже созданы** в `practice/` — создавать и копировать ничего не нужно.

```bash
cd ~/rust-learning
cargo test -p l02-text     # сейчас красные: стоят todo!()
```

1. Открой `practice/lNN-…/src/lib.rs`.
2. Замени `todo!()` на реализацию.
3. `cargo test -p lNN-…` — пока не позеленеет.
4. `cargo clippy -p lNN-… --all-targets -- -D warnings` и `cargo fmt -p lNN-…`.
5. Запиши разбор в `NOTES.md` (что было непонятно, какие ошибки поймал).

`cargo test --workspace` пока будет красным: в нём есть недоделанные лабы. Это нормально — гоняй тесты по конкретному пакету.

## Что значит «junior» и как это проверяется

Честно: 28 лекций **сами по себе** junior-уровня не дают — как и 28 лекций по Java не дают Java-разработчика. Дают его три вещи:

1. **Язык** — все конструкции, которые спросят на собеседовании.
2. **Практика** — 4 проекта и капстоун, где ты сам упрёшься в ошибки.
3. **Чужой код** — умение читать и объяснять не свой код.

Курс закрывает (1) полностью и (2) частично. Для (3) в конце будет раздел «читать чужой крейт» с конкретным планом.

### Как проверяем

- **Лекция 28** содержит чеклист на ~40 пунктов: «могу объяснить», «могу написать», «узнаю ошибку».
- **Мок-собеседование**: список из 30 вопросов с разбором ответов — не «правильный ответ», а «как рассуждать».
- **Критерий готовности**: все 4 проекта сданы, `clippy -D warnings` на них чистый, чеклист закрыт больше чем на 80%.

### Сколько времени

- лекции + тесты: ~45 минут на лекцию → **~21 час**;
- лабы: ~30 минут на лекцию → **~14 часов**;
- 4 проекта + капстоун: **~40 часов**;
- чтение чужого кода и повторение: **~30 часов**.

Итого **100–120 часов** плотной работы. Это несколько месяцев при 5–8 часах в неделю — то есть реалистичный срок «до junior», а не «за выходные».
