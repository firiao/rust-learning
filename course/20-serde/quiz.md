# Тест к лекции 20

Ответы — в конце, под `<details>`.

## Вопросы

**1.** Зачем два крейта: `serde` и `serde_json`?

a) один для чтения, другой для записи
b) `serde` — общие трейты и `derive`, `serde_json` — конкретный формат
c) `serde_json` нужен только для тестов

**2.** Что делает `#[derive(Serialize, Deserialize)]`?

a) генерирует код превращения структуры в текст и обратно
b) делает структуру публичной
c) проверяет JSON при компиляции

**3.** Что делает `#[serde(default)]`?

a) если поля нет в JSON — взять значение по умолчанию
b) сортирует поля
c) делает поле обязательным

**4.** Что вернёт `from_str` при `{"hidden_dim": "много"}`?

a) `Err` с сообщением `invalid type: string, expected usize`
b) `Ok` с `hidden_dim = 0`
c) панику

**5.** Почему `to_string` принимает ссылку `&config`?

a) чтобы не забирать владение: конфиг может понадобиться дальше
b) потому что `String` нельзя передать
c) это ошибка

**6.** Что означает ошибка `missing field 'hidden_dim'`?

a) лишнее поле в JSON
b) обязательное поле отсутствует, а `#[serde(default)]` у него нет
c) поле неправильного типа

---

## Ответы

<details>
<summary>Показать</summary>

**1 — b.** `serde` — протокол, `serde_json` — реализация формата. Есть `serde_yaml`, `toml`, `bincode`.

**2 — a.** Генерация `impl Serialize`/`Deserialize` (процедурный макрос).

**3 — a.** Поле можно опустить в JSON.

**4 — a.** Ошибка с указанием, что ожидалось и что пришло, плюс строка и колонка.

**5 — a.** `to_string(&config)` не забирает владение.

**6 — b.** Поле обязательное, но в JSON его нет.

</details>
