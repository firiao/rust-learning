# Лаба 8. `match`

**Время:** ~15 минут
**Тема:** `match` по диапазонам, строкам, кортежам; guard; `_`

## Цель

Три задачи, и в каждой нужен **другой вид шаблона**: диапазон, последовательность сцепленных условий
на двух значениях и сравнение со строкой.

## Крейт уже создан

Открывай `practice/l08-match` — в `src/lib.rs` три функции с `todo!()` и тесты.

```bash
cargo test -p l08-match      # 3 красных: стоят todo!()
```

## Реализуй

**1. `grade(score: u8) -> char`** — шаблоны-диапазоны.

```text
90..=100 -> 'A'    75..=89 -> 'B'    60..=74 -> 'C'    остальное -> 'F'
```

**2. `describe_point(x, y) -> String`** — `match` по **кортежу** `(x, y)` с `_` и guard:

```text
(0, 0)                 -> "начало координат"
(0, _)                 -> "на оси Y"
(_, 0)                 -> "на оси X"
(a, b) если a == b     -> "на диагонали"
иначе                  -> "обычная точка"
```

Порядок рукавов важен: `(0, _)` должен идти **после** `(0, 0)`, иначе начало координат уйдёт в «ось Y».

**3. `apply(op, a, b) -> i32`** — `match` по строке:

```text
"+" -> a + b    "-" -> a - b    "*" -> a * b    "/" -> a / b    иначе -> 0
```

## Эксперимент

Убери рукав `_ => "обычная точка"` в `describe_point` и запусти `cargo test -p l08-match`.

Запиши в `NOTES.md`: что говорит компилятор и какие значения он называет непокрытыми.

## Критерии приёмки

- [ ] 3 теста зелёные;
- [ ] везде используется `match`, никаких `if`/`else`;
- [ ] `(0, 0)` стоит раньше `(0, _)`;
- [ ] `clippy -D warnings` и `fmt --check` чистые после реализации;
- [ ] в `NOTES.md` записан текст ошибки `E0004`.

## Подсказки

<details>
<summary>`grade`</summary>

```rust
match score {
    90..=100 => 'A',
    75..=89 => 'B',
    60..=74 => 'C',
    _ => 'F',
}
```

`..=` — включительно (та же запись, что в `for`). Диапазоны не пересекаются, порядок между ними
не важен, но `_` обязателен: `u8` имеет 256 значений.

</details>

<details>
<summary>`describe_point`</summary>

```rust
let text = match (x, y) {
    (0, 0) => "начало координат",
    (0, _) => "на оси Y",
    (_, 0) => "на оси X",
    (a, b) if a == b => "на диагонали",
    _ => "обычная точка",
};
text.to_string()
```

Почему `to_string()`: рукава возвращают `&str` (литералы), а по контракту функция отдаёт `String`.

Guard `if a == b` — это **дополнительное условие** к шаблону: рукав срабатывает, только если подошёл
шаблон и условие истинно.

</details>

<details>
<summary>`apply`</summary>

```rust
match op {
    "+" => a + b,
    "-" => a - b,
    "*" => a * b,
    "/" => a / b,
    _ => 0,
}
```

`&str` в шаблонах сравнивается с литералами. `_` нужен потому, что строк может быть бесконечно много.

</details>

<details>
<summary>Эксперимент</summary>

```text
error[E0004]: non-exhaustive patterns: `(0, 1_i32..=i32::MAX)` and
many more not covered
```

Компилятор перечисляет, какие комбинации остались без рукава. Это и есть исчерпывающесть:
`match` обязан покрыть **все** возможные значения.

</details>
