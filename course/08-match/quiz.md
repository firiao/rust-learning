# Тест к лекции 8

Ответы — в конце, под `<details>`.

## Вопросы

**1.** В каком порядке проверяются рукава `match`?

a) в порядке возрастания значений
b) сверху вниз; срабатывает первый подошедший
c) компилятор выбирает самый точный

**2.** Зачем нужен `_`?

a) это комментарий
b) шаблон «любой остальной случай»; без него `match` по числам не исчерпывающий
c) он ускоряет `match`

**3.** Что вернёт `match 95 { 90..=100 => "A", _ => "F" }`?

a) `"A"`
b) `"F"`
c) ошибка

**4.** Как проверить сразу два значения?

a) двумя `if`
b) `match (x, y) { (0, 0) => ..., (0, _) => ..., ... }`
c) нельзя

**5.** Что делает `if` внутри рукава?

a) ничего, это опечатка
b) добавляет условие к шаблону (guard)
c) делает рукав необязательным

**6.** Почему `match n { 0 => "ноль", 1 => "один" }` для `i32` не компилируется?

a) не хватает `_`: `match` должен быть исчерпывающим
b) строки нельзя возвращать
c) нужно `return`

**7.** `match` — выражение или оператор?

a) оператор
b) выражение: его результат можно присвоить
c) зависит от типа

**8.** Что будет, если все рукава разного типа?

a) `error[E0308]: match arms have incompatible types`
b) выберется первый тип
c) работает

---

## Ответы

<details>
<summary>Показать</summary>

**1 — b.** Сверху вниз, первое совпадение выигрывает. Поэтому порядок рукавов важен: «широкий» рукав
сверху перехватит всё.

**2 — b.** `_` покрывает все остальные значения. Для `i32` перечислить все невозможно, поэтому без `_`
компилятор скажет `E0004: non-exhaustive patterns`.

**3 — a.** `95` попадает в `90..=100`.

**4 — b.** `match` по кортежу: `(0, 0)`, `(0, _)`, `(_, 0)` и т.д.

**5 — b.** Guard: `шаблон if условие =>`. Рукав срабатывает, только если подошёл шаблон **и** условие.

**6 — a.** Компилятор перечисляет непокрытое: отрицательные и `2..=i32::MAX`.

**7 — b.** `match` — выражение, как `if`. Все рукава дают значения одного типа.

**8 — a.** Тип результата общий для всех рукавов.

</details>
